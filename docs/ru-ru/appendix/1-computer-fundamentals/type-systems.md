# Введение в системы типов

::: tip Введение
**Почему `"1" + 1` в JavaScript даёт `"11"`, а в Python сразу выдаёт ошибку?** За этим стоит работа системы типов. Система типов — это «правила дорожного движения» языка программирования: она определяет, как можно использовать данные, с чем они могут участвовать в операциях, когда проверяется их легальность. Поняв систему типов, вы поймёте «различия в характере» разных языков.
:::

**Чему вас научит эта статья?**

После изучения этой главы вы получите:

- **Навык классификации**: освоение классификации по четырём квадрантам — статическая/динамическая, сильная/слабая типизация
- **Диагностику проблем**: увидев `TypeError`, вы быстро определите, дело в несоответствии типов или в неявном преобразовании
- **Выбор языка**: понимание того, почему TypeScript подходит для крупных проектов, а Python — для быстрого прототипирования
- **Вывод типов**: понимание того, как современные языки сочетают лаконичность и безопасность
- **Практическое осознание**: освоение типобезопасных привычек программирования

## 0. Общая картина: тип — это «удостоверение личности» данных

В реальном мире вы не засунете книгу в кофейную чашку — потому что это вещи разных «типов». В мире программирования так же: число, строка, булево значение, массив… у каждого вида данных своя «личность», определяющая, в каких операциях оно может участвовать.

**Система типов** — это и есть система правил, которой язык программирования управляет этими «личностями». Она отвечает на два ключевых вопроса:

::: tip Два ключевых вопроса системы типов
- **Когда проверять?** Проверять прямо при написании кода (статическая типизация) или только во время выполнения (динамическая типизация)?
- **Насколько строго?** Строго запрещать смешивание (сильная типизация) или автоматически преобразовывать за вас (слабая типизация)?
:::

## 1. Что такое система типов: правила дорожного движения для данных

<TypeSystemDemo />

Суть системы типов — это набор **ограничивающих правил**, которые сообщают компилятору или интерпретатору:

- Какое значение может хранить эта переменная?
- Можно ли сложить эти два значения?
- Какими должны быть параметры этой функции?

Мир без системы типов — как дорога без правил движения: любые данные могут участвовать в операциях с любыми, и результат совершенно непредсказуем.

| Роль системы типов | Пояснение | Пример |
|-------------|------|------|
| Предотвращение нелегальных операций | Блокировка бессмысленных операций | Нельзя делить строку |
| Предоставление документации | Тип — лучшая документация | `function add(a: number, b: number)` ясен с первого взгляда |
| Помощь инструментам IDE | Автодополнение, рефакторинг, переходы | Ввели `user.` — автоматически подсказываются все свойства |
| Оптимизация производительности | Зная тип, компилятор генерирует более быстрый код | Зная, что это целое — использует целочисленные инструкции |

## 2. Статическая vs динамическая типизация: когда проверять?

Это самое важное измерение классификации систем типов — **момент проверки**.

<StaticVsDynamicDemo />

::: tip Ключевое различие
- **Статическая типизация**: тип переменной определяется при компиляции, ошибку типов можно обнаружить ещё до запуска, сразу после написания кода. Представители: Java, TypeScript, Rust, Go.
- **Динамическая типизация**: тип переменной определяется во время выполнения, одна и та же переменная может сначала хранить число, потом строку. Представители: Python, JavaScript, Ruby, PHP.
:::

| Измерение | Статическая типизация | Динамическая типизация |
|------|---------|---------|
| Момент проверки | При компиляции (проверка ещё до запуска) | Во время выполнения (проверка при доходе до строки) |
| Обнаружение багов | Рано (узнаёшь сразу после написания) | Поздно (всплывает при действиях пользователя) |
| Гибкость | Ниже (тип фиксирован) | Выше (тип изменчив) |
| Поддержка IDE | Хорошая (автодополнение, рефакторинг) | Слабее (тип известен только во время выполнения) |
| Скорость разработки | Медленнее на старте (нужно писать типы) | Быстрее на старте (типы можно не указывать) |
| Стоимость сопровождения | Низкая (типы как документация) | Высокая (нехватка информации о типах) |

::: tip Тренд: динамические языки «статизируются»
Python добавил Type Hints, сообщество JavaScript переходит на TypeScript — динамические языки тоже перенимают преимущества статической типизации. Это говорит о том, что в крупных проектах преимущество безопасности статической типизации всё больше признаётся.
:::

## 3. Сильная vs слабая типизация: разрешать ли «тихое преобразование»?

Второе измерение классификации — **строгость преобразования типов**.

<StrongVsWeakDemo />

::: tip Ключевое различие
- **Сильная типизация**: не допускает неявного преобразования типов, при несоответствии типов выдаёт ошибку. Вы должны явно сказать языку: «я хочу преобразовать строку в число».
- **Слабая типизация**: допускает неявное преобразование типов, язык «по доброте» автоматически преобразует за вас. Но эта «доброта» часто приводит к неожиданным багам.
:::

| Измерение | Сильная типизация | Слабая типизация |
|------|-------|-------|
| `"1" + 1` | Ошибка или нужно явное преобразование | Автоматическое преобразование (может получиться `"11"` или `2`) |
| Безопасность | Высокая (не ошибётся втихую) | Низкая (неявное преобразование может привести к багу) |
| Удобство | Низкое (нужно преобразовывать вручную) | Высокое (автопреобразование избавляет от хлопот) |
| Предсказуемость | Высокая (поведение определено) | Низкая (правила преобразования сложны) |

## 4. Вывод типов: современное решение «лучшего из двух миров»

Ранние языки со статической типизацией (например, Java) требовали явно объявлять тип каждой переменной, что выходило очень многословно. Современные языки решают эту проблему через **вывод типов** — компилятор автоматически выводит тип, вам не нужно его писать, но он строго проверяет за вас.

<TypeInferenceFlowDemo />

::: tip Ценность вывода типов
Пишешь так же лаконично, как на динамическом языке, а компилятор проверяет так же строго, как в статическом. Это магистральное направление современных языков программирования.
- **TypeScript**: `let x = 42` автоматически выводится как `number`
- **Rust**: `let v = vec![1, 2, 3]` автоматически выводится как `Vec<i32>`
- **Kotlin**: `val name = "Alice"` автоматически выводится как `String`
- **Go**: `x := 42` короткое объявление переменной автоматически выводит тип
:::

## 5. Дженерики: написать один раз, применять для всех типов

Когда вы написали функцию «взять первый элемент массива», вы обнаружите: для массива чисел нужно написать одну, для массива строк — другую, для массива объектов — ещё одну… Код совершенно одинаков, отличается лишь тип. **Дженерики (Generics)** решают именно эту проблему — с помощью «параметра типа» вместо конкретного типа один код применяется для всех типов.

<GenericTypeDemo />

::: tip Ключевая ценность дженериков
- **Переиспользование кода**: одна функция/класс применяется для всех типов, не нужно писать повторно
- **Типобезопасность**: в отличие от `any`, не отказывается от проверки типов, дженерики на всём протяжении сохраняют информацию о типах
- **Ограничения типов**: с помощью `extends` ограничивают диапазон дженерика — и гибко, и безопасно
:::

| Особенность дженериков | Пояснение | Пример |
|---------|------|------|
| Дженерик-функция | Параметры/возвращаемое значение функции используют параметр типа | `function first<T>(arr: T[]): T` |
| Дженерик-класс | Свойства/методы класса используют параметр типа | `class Box<T> { value: T }` |
| Ограничение дженерика | С помощью extends ограничивают диапазон T | `<T extends HasLength>` |
| Несколько параметров типа | Одновременное использование нескольких типовых переменных | `function pair<K, V>(k: K, v: V)` |

## 6. Практика типобезопасности: распространённые ловушки и защита

Теория изучена — посмотрим на самые лёгкие способы наступить на типовые грабли в реальной разработке. Эти ловушки не зависят от языка, с ними сталкивается почти каждый разработчик.

<TypeSafetyPracticeDemo />

::: tip Четыре золотых правила типобезопасности
1. **Включите строгий режим**: `strict: true` в TypeScript, `mypy --strict` в Python
2. **Избегайте any**: используйте `unknown` вместо `any`, что вынуждает вас проверить тип перед использованием
3. **Явно обрабатывайте null**: безопасно обращайтесь через опциональную цепочку `?.` и слияние с null `??`
4. **Определяйте интерфейсы для API**: внешним данным никогда нельзя доверять, используйте двойную защиту интерфейс + проверка во время выполнения
:::

| Ловушка | Степень опасности | Средство защиты |
|------|---------|---------|
| Ссылка на null/undefined | ⭐⭐⭐⭐⭐ | strictNullChecks + опциональная цепочка |
| Злоупотребление типом any | ⭐⭐⭐⭐ | unknown + охранник типов |
| Неявное преобразование типов | ⭐⭐⭐ | Строгое сравнение === + ESLint |
| Несогласованность типов в массиве | ⭐⭐⭐ | Явное объявление типа элементов массива |

## 7. Квадрантная карта типов языков: «портрет» языка программирования

Объединив два измерения — «статическая/динамическая» и «сильная/слабая» — получаем квадрантную карту классификации. Любой язык программирования можно поместить в эту карту.

<LanguageTypeModelDemo />

| Квадрант | Особенности | Языки-представители | Сценарий применения |
|------|------|---------|---------|
| Статическая + сильная типизация | Самые безопасные, строгая проверка при компиляции | Rust, Java, Haskell | Крупные системы, критичные к безопасности |
| Статическая + слабая типизация | Проверка при компиляции, но допускает неявное преобразование | C, C++ | Системное программирование, чувствительное к производительности |
| Динамическая + сильная типизация | Проверка во время выполнения, без неявного преобразования | Python, Ruby | Скрипты, быстрое прототипирование |
| Динамическая + слабая типизация | Самые гибкие, но и самые подверженные багам | JavaScript, PHP | Веб-фронтенд, небольшие скрипты |

::: tip «Лучшей» системы типов не существует
При выборе языка система типов — один из важных факторов:
- **Быстрое прототипирование**: динамическая типизация (Python) даёт высокую скорость разработки
- **Крупные проекты**: статическая типизация (TypeScript, Java) даёт низкую стоимость сопровождения
- **Системное программирование**: сильная типизация + статическая (Rust) даёт наивысшую безопасность
- **Командное взаимодействие**: статическая типизация обеспечивает лучшую читаемость кода и поддержку IDE
:::

## Итог

Система типов — ключевой ракурс для понимания различий между языками программирования. Это не сухая теория, а то, что напрямую влияет на ваш опыт написания кода и на качество кода.

Вспомним ключевые моменты этой главы:

1. **Тип — это удостоверение личности**: у каждого вида данных есть тип, тип определяет, в каких операциях данные могут участвовать
2. **Статическая vs динамическая**: когда проверять типы — при компиляции или во время выполнения
3. **Сильная vs слабая**: допускается ли неявное преобразование типов
4. **Вывод типов**: современные языки дают вам насладиться лаконичностью динамики и безопасностью статики
5. **Дженерики**: с помощью параметров типов достигается переиспользование кода, сочетая гибкость и типобезопасность
6. **Практика типобезопасности**: ссылка на null, злоупотребление any, неявное преобразование — самые распространённые типовые ловушки
7. **Классификация по четырём квадрантам**: лучшей системы типов нет, есть лишь выбор, наиболее подходящий для сценария
