## 0. Как человек «разговаривает» с компьютером?

Представьте, что вам нужно общаться с роботом, понимающим только двоичный код:

- **Печатать напрямую 0 и 1** — самое примитивное, крайне неэффективно, написал 0 вместо 1 — и всё неверно (машинный язык)
- **Использовать мнемоники** — `MOV AX, 1` куда узнаваемее, чем `10110000 00000001` (язык ассемблера)
- **Использовать близкое к естественному языку** — `int sum = 1 + 2;` человек может прочитать напрямую (высокоуровневый язык)

**Язык программирования — это мост между человеком и компьютером**, и более 70 лет он эволюционирует в направлении «всё ближе к человеческому мышлению».

## 2. Парадигмы программирования: способ осмысления задачи

Парадигма программирования — это не особенность языка, а **образ мышления** — подобно тому, как в письме есть разные жанры: поэзия, проза, эссе.

### 2.1 Императивная — «шаг за шагом говорим компьютеру, что делать»

```c
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += arr[i];
}
```

### 2.2 Объектно-ориентированная — «инкапсулируем данные и поведение в объекты»

```python
class Dog:
    def __init__(self, name):
        self.name = name
    def bark(self):
        print(f"{self.name} says woof!")
```

### 2.3 Функциональная — «композиция чистых функций, без изменения состояния»

```haskell
sum = foldl (+) 0
-- одинаковый вход всегда даёт одинаковый выход
```

### 2.4 Декларативная — «говорим только что делать, а не как»

```sql
SELECT name FROM users WHERE active = true
-- база данных сама решает, как запросить быстрее всего
```

::: tip 💡 В реальной разработке
Большинство современных языков **мультипарадигмальны**. Python поддерживает и объектно-ориентированный, и функциональный подход; JavaScript тоже. Не надо ломать голову, «какая парадигма лучше всех» — выбирайте наиболее подходящий способ исходя из задачи.
:::

## 3. Система типов: правила дорожного движения для данных

| | Сильная типизация | Слабая типизация |
|---|---|---|
| **Статическая** | Java, Rust, TypeScript — самые безопасные | C, C++ — эффективны, но требуют осторожности |
| **Динамическая** | Python, Ruby — гибкие и безопасные | JavaScript, PHP — гибкие, но подвержены ошибкам |

**Ключевой вопрос**: чему равно `"1" + 1`?
- **JavaScript (слабая типизация)**: `"11"` — втихую преобразовал за вас
- **Python (сильная типизация)**: `TypeError` — заставляет вас всё продумать самому

## 4. Компилируемые vs интерпретируемые

| | Компилируемые | Интерпретируемые | JIT |
|---|---|---|---|
| **Процесс** | Сначала перевод всего, затем выполнение | Чтение и сразу выполнение | Сначала интерпретация, затем горячий код компилируется |
| **Скорость** | Самая высокая | Более медленная | Средняя |
| **Отладка** | Нужно ждать компиляцию | Мгновенная обратная связь | Мгновенно + оптимизация |
| **Представители** | C, Rust, Go | Python, Ruby | Java, JavaScript |

## 5. Как выбрать язык программирования?

### Выбор по сценарию

| Сценарий | Рекомендуемые языки | Причина |
|---|---|---|
| **Веб-фронтенд** | JavaScript, TypeScript | Браузер знает только JS |
| **Веб-бэкенд** | Go, Java, Python, Node.js | Зрелая экосистема |
| **Мобильная разработка** | Swift (iOS), Kotlin (Android) | Рекомендованы официально |
| **ИИ / данные** | Python | PyTorch, Pandas — всё на Python |
| **Системное программирование** | C, Rust | Прямое управление железом |
| **Облачные технологии** | Go, Rust | Docker/K8s написаны на Go |

### Советы по маршруту обучения

1. **Python** — самый простой синтаксис, точка входа в эпоху ИИ
2. **JavaScript** — обязателен для веб-разработки, владеет и фронтендом, и бэкендом
3. **TypeScript** — добавляет в JS систему типов, опыт статической типизации
4. **Go или Rust** — понимание компилируемых языков и низкоуровневых концепций
