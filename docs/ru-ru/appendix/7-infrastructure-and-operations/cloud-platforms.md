Эта глава строится вокруг одного ключевого вопроса: **как с нуля понять и начать использовать облачные сервисы?** Мы используем реальные сценарии, наглядные аналогии и практические шаги, чтобы помочь вам построить полную карту понимания облачных сервисов.

## 0. Введение: почему всё больше компаний перестают покупать серверы?

Представьте себе такой сценарий:

Мин запустил стартап в 2010 году и хотел сделать сайт. Что он пережил?

Сначала он за 20 тысяч юаней купил сервер Dell, затем связался с дата-центром IDC, ежемесячно платя 3000 юаней за размещение. Дальше он сам устанавливал Linux, настраивал окружение, ещё и беспокоился об оборудовании — сгорел диск, надо менять самому, перегрелась машина — решать самому. Самое мучительное было то, что когда пользователей внезапно становилось много и система не выдерживала, ему снова приходилось покупать новый сервер. Через год Мин потратил 50 тысяч, а загрузка серверов составляла лишь 10%.

А компания Хун запустила стартап в 2024 году, как поступила она?

Она открыла сайт облачного провайдера, зарегистрировала аккаунт, несколькими кликами мыши создала облачный сервер за 2 минуты. Сколько используешь — столько платишь, не используешь — не платишь. Трафик вырос — один клик, чтобы обновить конфигурацию. Хочешь открыть филиал в США? Просто смени регион. Через месяц Хун потратила 500 юаней при загрузке серверов 80%.

**Интуитивно мы думаем, что: «облачный сервис — это просто аренда серверов».**

Но суть облачных сервисов далеко не сводится к этому — это **революция вычислительных мощностей**.

Раньше предприятиям приходилось проходить долгий путь: купить сервер, найти дата-центр, поставить систему, беспокоиться об оборудовании, оставаться беспомощными при всплеске трафика. Теперь нужно лишь зарегистрировать аккаунт, сделать несколько кликов мышью, платить по потребности, автоматически масштабироваться, разворачивать по всему миру. Эта трансформация похожа на переход от рытья собственного колодца за водой к водопроводу, из крана которого течёт вода.

## 1. Что такое облачный провайдер?

### 1.1 Вычислительный сервис, подобный коммунальной компании

Суть облачного провайдера — **упаковать вычислительные мощности, мощности хранения, сетевые мощности в стандартизированные сервисы** и предоставлять их пользователям через интернет, подобно тому, как водопроводная компания поставляет воду, а электрическая — электричество.

Хитрость этой модели — в **использовании по требованию**. Вам не нужно заранее покупать массу оборудования, достаточно платить по фактическому объёму использования. Нужно больше ресурсов? Один клик. Некоторые сервисы даже тарифицируются посекундно, что чрезвычайно гибко. Кроме того, у облачных провайдеров есть дата-центры в десятках стран, вы можете разворачивать приложения по всему миру, все операции — самообслуживание, доступны 24 часа в сутки, без ручного согласования.

### 1.2 Различие между облачными сервисами и традиционным хостингом

Традиционный хостинг в IDC похож на покупку собственного генератора для выработки электричества. Сначала нужно купить оборудование (сервер), затем найти место для размещения (хостинг в дата-центре), и ещё самостоятельно обслуживать (ставить систему, чинить оборудование). Если электричества не хватает, нужно покупать ещё один генератор. Этот процесс может занять от нескольких дней до нескольких недель, затраты фиксированные — платить нужно вне зависимости от использования.

Облачные сервисы же похожи на подключение к электросети. Вам не нужно покупать генератор, достаточно протянуть провод (зарегистрировать аккаунт), а затем платить по объёму потребления электричества. Нужно больше энергии? Смените тариф на более мощный — готово за несколько минут. В этой модели затраты переменные, сколько используешь — столько платишь, а облачный провайдер отвечает за всё обслуживание оборудования, вам остаётся лишь сосредоточиться на своём бизнесе.

### 1.3 Публичное облако, частное облако и гибридное облако

Как у ресторанов есть разные модели работы, так и у облачных сервисов есть три типа.

**Публичное облако** похоже на общественный ресторан — им может пользоваться любой, ресурсы общие. AWS, Alibaba Cloud, Azure — это публичные облака, подходящие подавляющему большинству предприятий и частных лиц. Это акцент данной книги, поскольку оно используется чаще всего и лучше всего подходит для обучения.

**Частное облако** похоже на личную кухню — вы строите его сами и единолично владеете ресурсами. OpenStack, VMware — типичные представители, подходят крупным предприятиям, правительству, банкам — для сценариев с крайне высокими требованиями к безопасности данных.

**Гибридное облако** — это сочетание двух: часть бизнеса использует публичное облако, часть — частное. У всех провайдеров есть свои решения, оно подходит для сценариев, где нужны одновременно и соответствие требованиям, и эластичность.

## 2. Какие есть известные облачные провайдеры?

### 2.1 Три международных гиганта: AWS, Azure, Google Cloud

На мировом рынке облачных сервисов доминирующее положение занимают три провайдера.

**AWS (Amazon Web Services)** — облачный сервис, запущенный Amazon в 2006 году, первый по доле мирового рынка, около 32%. Это как «универмаг» в мире облачных сервисов — самый полный ассортимент сервисов, более 200 видов, самые зрелые и стабильные функции, богатейшие ресурсы документации и сообщества. Цена хоть и выше, но соотношение цена/качество отличное, особенно подходит для компаний, выходящих за рубеж, стартапов и крупных интернет-компаний.

**Microsoft Azure** — облачный сервис, запущенный Microsoft в 2010 году, второй по доле мирового рынка, около 23%. Его главное преимущество — глубокая интеграция с экосистемой Windows, Office, богатые ресурсы корпоративных клиентов, сильные возможности гибридного облака, особая дружелюбность к разработчикам на .NET. Если ваша компания уже использует технологический стек Microsoft, Azure — естественный выбор.

**Google Cloud Platform (GCP)** — облачный сервис, запущенный Google в 2011 году, третий по доле мирового рынка, около 10%. Он лидирует в области Kubernetes, анализа данных, ИИ, обладает сильной способностью к технологическим инновациям, цена относительно ниже. Но доля рынка меньше, экосистема не так совершенна, как у первых двух, подходит технологически ориентированным компаниям, контейнеризированным приложениям и ИИ-проектам.

### 2.2 Три китайских гиганта: Alibaba Cloud, Tencent Cloud, Huawei Cloud

На китайском рынке облачных сервисов также есть три основных провайдера.

**Alibaba Cloud** — подразделение облачных вычислений, основанное Alibaba в 2009 году, первое по доле китайского рынка, около 40%. Как самый ранний и зрелый облачный провайдер в стране, Alibaba Cloud обладает полным ассортиментом сервисов, глубоким технологическим опытом в e-commerce и распродажах «Двойного 11». Цена хоть и относительно выше, но стабильность и полнота функций — первоклассные, особенно подходит отечественным предприятиям и e-commerce проектам.

**Tencent Cloud** — облачное подразделение, основанное Tencent в 2013 году, второе по доле китайского рынка, около 15%. Оно сильно в играх, аудио и видео, хорошо сочетается с экосистемой WeChat, QQ, цена относительно ниже, в последние годы развивается стремительно. Если вы делаете игровой, социальный или стриминговый проект, Tencent Cloud — неплохой выбор.

**Huawei Cloud** — облачное подразделение, основанное Huawei в 2015 году, третье по доле китайского рынка, около 10%. Оно обладает сильным опытом в аппаратных технологиях, богатыми ресурсами государственных и корпоративных клиентов, сильными возможностями в области безопасности и соответствия, отличается ИИ-чипами (Ascend). Подходит для государственных проектов, крупных госпредприятий и производства.

### 2.3 Как выбрать облачного провайдера?

Выбор облачного провайдера похож на выбор съёмного жилья — нужно учитывать множество факторов: расположение, цену, инфраструктуру и т.п.

**Сначала смотрите на целевой рынок**. Где в основном находятся ваши пользователи? Если пользователи в Китае — выбирайте Alibaba Cloud или Tencent Cloud; если за рубежом — AWS или Azure; если бизнес глобальный — выбирайте провайдера с покрытием множества регионов.

**Затем смотрите на технологический стек**. Какие технологии вы используете? Если технологии Microsoft — выбирайте Azure; если Kubernetes, big data — выбирайте Google Cloud; если общий сценарий — AWS будет надёжным выбором.

**Далее смотрите на стоимость**. Для пробы небольшого проекта можно выбрать что подешевле, например Tencent Cloud или UCloud; для крупного продакшена нужно смотреть на общую стоимость — AWS в долгосрочной перспективе может оказаться экономнее.

**Наконец смотрите на экосистему**. Если вы уже используете другие сервисы, например GitHub, Office 365, выбор провайдера из той же экосистемы будет удобнее.

Практический совет таков: новичкам или для небольших проектов выбирайте Alibaba Cloud или Tencent Cloud, поскольку документация на китайском, а поддержка внутри страны; для зарубежных проектов выбирайте AWS, поскольку он самый зрелый и с лучшим глобальным покрытием; крупным предприятиям может понадобиться мульти-облачная стратегия — разный бизнес на разных облаках.

## 3. Как обычно используют облачные сервисы?

### 3.1 Полный процесс от регистрации до запуска

Первый шаг использования облачных сервисов — регистрация аккаунта. Этот процесс похож на открытие счёта в банке — нужно подтвердить вашу личность. Откройте официальный сайт облачного провайдера, нажмите «Бесплатная регистрация», заполните email и пароль, подтвердите номер телефона, затем загрузите удостоверение личности или документы предприятия для верификации, и наконец привяжите способ оплаты. Весь процесс занимает примерно от 10 до 20 минут.

После регистрации вам нужно усвоить несколько ключевых концепций. **Регион (Region)** — это территория расположения дата-центра облачного сервиса, например Восточный Китай (Ханчжоу), Восток США (Вирджиния), Азиатско-Тихоокеанский регион (Сингапур). Принцип выбора: чем ближе к вашим пользователям, тем лучше, поскольку ниже задержка. **Зона доступности (Availability Zone, AZ)** — это несколько дата-центров в пределах одного региона, изолированных друг от друга для повышения доступности. Если одна зона доступности упадёт, другая продолжит работать. **Экземпляр (Instance)** — это виртуальный сервер, например облачный сервер с 2 ядрами и 4 ГБ памяти, тарификация по времени или по объёму.

### 3.2 Создание первого облачного сервера

Процесс создания облачного сервера похож на сборку компьютера, но конфигурация выбирается кликами на веб-странице. Сначала выберите модель оплаты: для тестовой среды — оплата по объёму, для длительной работы — годовая/помесячная подписка. Затем выберите регион — ближайший к вам, например Восточный Китай — Ханчжоу. По спецификации экземпляра: 2 ядра и 4 ГБ достаточно для тестовой среды. В качестве образа выберите операционную систему, например CentOS 7.9 или Ubuntu 20.04. Для хранилища используйте системный диск 40 ГБ, для сети — VPC-сеть по умолчанию, а оплата полосы пропускания по объёму трафика выйдет экономнее. Наконец задайте пароль пользователя root, не забудьте его сохранить. Весь процесс занимает около 5 минут, после создания экземпляра подождите 1-2 минуты — и можно пользоваться.

### 3.3 Подключение к облачному серверу и развёртывание приложения

Для подключения к серверу Linux рекомендуется использовать SSH. Способ входа по паролю: `ssh root@публичный_IP_вашего_сервера`, затем ввести пароль. Вход по ключу безопаснее, способ: `ssh -i ваш_приватный_ключ.pem root@публичный_IP_вашего_сервера`.

После подключения к серверу можно развёртывать приложение. Сначала обновите систему: в CentOS — `sudo yum update -y`, в Ubuntu — `sudo apt update && sudo apt upgrade -y`. Затем установите необходимое ПО, например Node.js. После этого загрузите код, можно через git или scp. Наконец установите зависимости и запустите приложение.

### 3.4 Распространённые сценарии использования

**Хостинг личного сайта или блога** требует облачного сервера плюс доменное имя, достаточно 1 ядра и 2 ГБ, стоимость около 50-100 юаней в месяц, технологический стек можно использовать Nginx со статическими файлами или WordPress.

**Развёртывание API-бэкенда** требует облачного сервера плюс базы данных, от 2 ядер и 4 ГБ, стоимость около 200-500 юаней в месяц, технологический стек можно использовать Node.js или Python в связке с MySQL или PostgreSQL.

**Хранение изображений или видео** рекомендуется использовать объектное хранилище, тарификация по объёму хранения и трафику, стоимость от нескольких до нескольких сотен юаней в месяц. Преимущества: не нужно управлять дисками, автоматическое резервное копирование, а также можно ускорить с помощью CDN.

## 4. Как купить и вызывать API?

### 4.1 Модели тарификации облачных сервисов

У облачных сервисов есть множество способов тарификации, понимание которых поможет вам сэкономить немало денег.

**Оплата по требованию (Pay-as-you-go)** похожа на разовую покупку билета в кино — сколько используешь, столько платишь, не используешь — не платишь. Подходит для тестовой среды, проектов с нестабильным трафиком. Облачный сервер тарифицируется почасово, объектное хранилище — по ГБ плюс число запросов, ИИ-API — по числу вызовов.

**Годовая/помесячная подписка или зарезервированные экземпляры** похожи на покупку месячного или годового абонемента — обязуясь использовать определённый срок, получаете скидку, обычно можно сэкономить от 30% до 60%. Подходит для длительно и стабильно работающей продакшен-среды. Например, сервер с 2 ядрами и 4 ГБ по требованию стоит 200 юаней в месяц, а подписка на 1 год — возможно, лишь 140 юаней в месяц.

**Спотовые или вытесняемые экземпляры** похожи на резервный билет — цена очень низкая, можно сэкономить до 90%, но экземпляр может быть принудительно изъят. Подходит для пакетной обработки, отказоустойчивых задач, например обработки данных, задач рендеринга. Риск в том, что при дефиците ресурсов у облачного провайдера экземпляр будет принудительно изъят.

**Serverless с оплатой по числу вызовов** похож на такси — не нужно заботиться о серверах, важно только число вызовов. Тарификация: число вызовов плюс время вычислений плюс трафик, подходит для API-эндпоинтов, событийно-управляемых задач. Например, в Alibaba Cloud Function Compute первый 1 миллион вызовов бесплатно, сверх этого — 1,33 юаня за миллион.

### 4.2 Полный процесс покупки вызовов API

На примере вызова API Tongyi Qianwen весь процесс делится на четыре шага.

**Первый шаг — подключение сервиса**. Откройте платформу ИИ или платформу машинного обучения PAI облачного провайдера, найдите Tongyi Qianwen или DashScope, нажмите «Подключить сейчас» или «Бесплатная пробная версия», займёт около 2 минут.

**Второй шаг — получение API Key**. Зайдите в управление API-KEY в консоли, нажмите «Создать мой API-KEY», скопируйте и сохраните этот Key. Важное замечание: API Key показывается только один раз, сохраните его немедленно.

**Третий шаг — настройка прав**. Зайдите в управление доступом (RAM) или управление правами (IAM), создайте пользователя или роль, выдайте только необходимые права, например только вызов Tongyi Qianwen, без возможности удалять серверы. Это принцип минимальных привилегий.

**Четвёртый шаг — тестирование вызова**. На Python или JavaScript выполните первый вызов, чтобы проверить, корректно ли работает API.

## 5. Практика: развёртывание сайта с нуля

### 5.1 Сценарий и выбор решения

Предположим, вы фронтенд-разработчик и хотите развернуть личный блог. Требования: статический сайт (HTML/CSS/JS), собственное доменное имя, высокая скорость доступа по всему миру, минимально возможная стоимость.

Есть три варианта на выбор. Вариант с облачным сервером — средняя стоимость, средняя сложность, подходит для сценариев, требующих бэкенд-сервиса. Вариант «объектное хранилище плюс CDN» — низкая стоимость, низкая сложность, подходит для чисто статического сайта, это наш рекомендуемый вариант. Вариант Serverless — крайне низкая стоимость, средняя сложность, подходит для динамического контента.

Причина рекомендации «объектное хранилище плюс CDN»: минимальная стоимость (возможно, бесплатно), простейшая настройка, максимальная скорость (ускорение CDN).

### 5.2 Шаги реализации

**Шаг 1: подготовка файлов сайта**. Создайте простой index.html:

```html
<!DOCTYPE html>
<html>
<head>
  <title>我的博客</title>
</head>
<body>
  <h1>欢迎来到我的博客</h1>
  <p>这是我的第一篇文章。</p>
</body>
</html>
```

**Шаг 2: создание Bucket объектного хранилища**. Войдите в облачную консоль, найдите объектное хранилище (OSS/S3), нажмите «Создать Bucket». Настройте имя (например, my-blog-2024, глобально уникальное), выберите регион (ближайший к вам), установите права на публичное чтение (сайт должен быть доступен).

**Шаг 3: загрузка файлов**. Зайдите в Bucket, нажмите «Загрузить файлы», выберите index.html, дождитесь завершения загрузки.

**Шаг 4: настройка хостинга статического сайта**. Зайдите в настройки Bucket, найдите «Статические страницы» или «Хостинг сайта», включите функцию, задайте страницу по умолчанию index.html, сохраните настройки.

**Шаг 5: привязка доменного имени (опционально)**. Купите доменное имя (например, Alibaba Cloud Wanwang), добавьте запись CNAME, указывающую на домен Bucket, привяжите пользовательский домен в Bucket, настройте HTTPS.

**Шаг 6: настройка CDN (рекомендуется)**. Подключите сервис CDN, добавьте домен для ускорения, выберите источник (ваш Bucket), дождитесь вступления CDN в силу (от нескольких минут до нескольких часов).

### 5.3 Оценка стоимости

Оценка месячной стоимости: объектное хранилище 0-5 юаней (тарификация по объёму хранения), трафик CDN 0-10 юаней (тарификация по трафику, есть бесплатный лимит), доменное имя 5-10 юаней (в пересчёте за год). Итого 5-25 юаней в месяц, для небольшого сайта может быть полностью бесплатно.

## 6. Заключение и следующие шаги

### 6.1 Обзор ключевых моментов

Суть облачных сервисов можно резюмировать так: облачный провайдер — это коммунальная компания вычислительных мощностей, предоставляющая возможности использования по требованию, глобального развёртывания, самообслуживания. Процесс использования: выбрать провайдера, зарегистрировать аккаунт, создать ресурсы, настроить права, мониторить расходы.

Ключевые точки принятия решений включают: выбор провайдера — смотреть на рынок, технологический стек, стоимость; выбор модели тарификации — взвешивать между оплатой по требованию, годовой/помесячной подпиской, Serverless; настройка прав — следовать принципу минимальных привилегий, включить MFA, регулярно аудировать; контроль расходов — мониторить использование, применять скидки, своевременно освобождать ненужные ресурсы.

### 6.2 Рекомендации по пути обучения

Первая неделя — изучение теоретических основ, понимание базовых концепций облачных сервисов, регистрация облачного аккаунта, создание первого облачного сервера. Вторая неделя — практика: развернуть статический сайт, настроить домен и CDN, изучить базовые команды Linux. Третья неделя — изучение продвинутых навыков, включая управление правами (IAM), мониторинг и оповещения, оптимизацию расходов. Четвёртая неделя — практический проект: развернуть полноценное приложение, настроить базу данных и хранилище, реализовать автомасштабирование.

### 6.3 Рекомендуемые ресурсы

Официальная документация включает Центр документации Alibaba Cloud, китайскую документацию AWS, документацию Tencent Cloud. Обучающие платформы — Alibaba Cloud University, бесплатный пакет AWS, лаборатория Tencent Cloud. Ресурсы сообщества — сообщество Cloud Native, китайский сайт Serverless, колонка по облачным вычислениям InfoQ.

## 7. Таблица соответствия терминов

| Английский термин | Перевод | Пояснение |
| :--- | :--- | :--- |
| **Cloud Provider** | Облачный провайдер | Компания, предоставляющая облачные вычислительные сервисы, например AWS, Alibaba Cloud |
| **Region** | Регион | Географическая территория расположения дата-центра |
| **Availability Zone** | Зона доступности | Независимый дата-центр в пределах одного региона |
| **Instance** | Экземпляр | Один виртуальный сервер |
| **Image/AMI** | Образ | Преднастроенный шаблон операционной системы |
| **VPC** | Виртуальное частное облако | Изолированная виртуальная сетевая среда |
| **IAM/RAM** | Управление идентификацией и доступом | Система управления правами |
| **User** | Пользователь | Конкретная идентичность |
| **Group** | Группа пользователей | Совокупность пользователей |
| **Role** | Роль | Временная идентичность |
| **Policy** | Политика | JSON-документ, определяющий права |
| **API Key** | API-ключ | Учётные данные для вызова API |
| **AccessKey** | Ключ доступа | Учётные данные для программного доступа (ID + Secret) |
| **MFA** | Многофакторная аутентификация | Способ входа, требующий пароль плюс код подтверждения |
| **CDN** | Сеть доставки контента | Сервис глобального ускорения, кэширующий статические ресурсы |
| **OSS/S3** | Объектное хранилище | Сервис хранения файлов |
| **ECS/EC2** | Облачный сервер | Сервис виртуального хоста |
| **RDS** | Сервис реляционных баз данных | Управляемая база данных |
| **Serverless** | Бессерверный | Модель вычислений без управления серверами |
| **Pay-as-you-go** | Оплата по требованию | Модель тарификации «сколько используешь — столько платишь» |
| **Reserved Instance** | Зарезервированный экземпляр | Модель тарификации с годовой/помесячной подпиской |
| **Spot Instance** | Вытесняемый экземпляр | Дешёвый экземпляр, который может быть изъят |
