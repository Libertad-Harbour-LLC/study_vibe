## 1. Файловая система: всё есть файл

Одна из ключевых философий Linux — **всё есть файл**. Обычный файл — файл, каталог — файл, жёсткий диск — файл, и даже сетевые соединения, информация о процессах — тоже файлы. Эта единая абстракция позволяет одним набором инструментов (чтение, запись, контроль прав) работать почти со всеми системными ресурсами.

<LinuxFileSystemDemo />

### Запоминаем структуру каталогов

Представьте файловую систему Linux как перевёрнутое дерево:

```
/                    ← корневой каталог (корень дерева)
├── home/            ← дом пользователей (все ваши файлы здесь)
├── etc/             ← файлы конфигурации («панель настроек» системы)
├── var/             ← изменяющиеся данные (логи, кэш)
├── usr/             ← программы, установленные пользователем
├── tmp/             ← временные файлы (исчезают при перезагрузке)
├── proc/            ← информация о процессах (виртуальная, не занимает диск)
├── dev/             ← файлы устройств (диски, терминалы)
├── bin/             ← базовые команды (ls, cp, mv)
├── sbin/            ← команды системного администрирования (нужен root)
├── opt/             ← стороннее ПО
└── root/            ← домашний каталог пользователя root
```

### Два способа записи пути

| Тип | Формат | Пример | Пояснение |
|------|------|------|------|
| Абсолютный путь | Начинается с `/` | `/home/alice/code/app.js` | Отсчёт от корня, без неоднозначности |
| Относительный путь | Начинается от текущего каталога | `./code/app.js` или `../config` | `.` — текущий каталог, `..` — родительский каталог |

::: tip Сила философии «всё есть файл»
Хотите узнать информацию о CPU? Читаете файл: `cat /proc/cpuinfo`
Хотите узнать использование памяти? Читаете файл: `cat /proc/meminfo`
Хотите получить случайные числа? Читаете файл: `cat /dev/urandom`
Хотите отбросить вывод? Пишете в файл: `echo "no thanks" > /dev/null`

Не нужен специальный API, достаточно чтения и записи файлов. В этом и заключается элегантность философии Unix.
:::

## 2. Часто используемые команды

Команды Linux следуют единому формату: `команда [опции] [аргументы]`. Например, в `ls -la /home` `ls` — команда, `-la` — опции, `/home` — аргумент.

<LinuxCommandDemo />

### 10 самых часто используемых команд

Если можно запомнить только 10 команд, запомните эти:

| Команда | Назначение | Подсказка для запоминания |
|------|------|----------|
| `ls` | Вывести список файлов | list |
| `cd` | Сменить каталог | change directory |
| `cat` | Посмотреть файл | concatenate |
| `grep` | Поиск текста | global regular expression print |
| `find` | Поиск файлов | это и есть find |
| `ps` | Посмотреть процессы | process status |
| `tail -f` | Смотреть логи в реальном времени | смотреть «хвост» файла, -f — это follow |
| `chmod` | Изменить права | change mode |
| `curl` | Отправить HTTP-запрос | client URL |
| `ssh` | Удалённый вход | secure shell |

### Искусство комбинирования команд

Сила Linux не в отдельной команде, а в **комбинировании команд**. Через канал `|` объединяя несколько простых команд, решают сложные задачи:

```bash
# 找出占用 CPU 最多的 5 个进程
ps aux --sort=-%cpu | head -6

# 统计日志中出现最多的错误类型
grep "ERROR" app.log | awk '{print $4}' | sort | uniq -c | sort -rn | head -10

# 查找大于 100MB 的文件
find / -size +100M -type f 2>/dev/null

# 实时监控日志中的错误
tail -f /var/log/app.log | grep --color "ERROR"
```

::: tip Философия Unix
«Делай одно дело и делай его хорошо.» Каждая команда отвечает лишь за одну функцию, а сложные операции реализуются комбинированием через канал. Вот почему команды Linux короткие — это кубики, а не швейцарский нож.
:::

## 3. Модель прав

Linux — многопользовательская система, и модель прав является краеугольным камнем безопасности. У каждого файла есть три группы прав, контролирующие, что могут делать соответственно **владелец (Owner)**, **группа-владелец (Group)** и **остальные (Others)**.

### Чтение вывода `ls -l`

```bash
$ ls -l app.js
-rwxr-xr-- 1 alice developers 2048 Jan 15 10:30 app.js
│├──┤├──┤├──┤   │     │          │
│ │   │   │     │     │          └── размер файла
│ │   │   │     │     └── группа-владелец
│ │   │   │     └── владелец
│ │   │   └── права остальных: r-- (только чтение)
│ │   └── права группы: r-x (чтение + выполнение)
│ └── права владельца: rwx (чтение + запись + выполнение)
└── тип файла: - обычный файл, d каталог, l ссылка
```

### Три вида операций с правами

| Право | Буква | Число | Значение для файла | Значение для каталога |
|------|------|------|-------------|-------------|
| Чтение | `r` | 4 | Просмотр содержимого файла | Вывод содержимого каталога (ls) |
| Запись | `w` | 2 | Изменение содержимого файла | Создание/удаление файлов в каталоге |
| Выполнение | `x` | 1 | Запуск программы/скрипта | Вход в каталог (cd) |

<LinuxPermissionsDemo />

### Быстрый подсчёт числовых прав

Три числа соответственно представляют права Owner, Group, Others, каждое число — сумма r(4) + w(2) + x(1):

```
chmod 755 script.sh
  7 = rwx (4+2+1)  → владелец: чтение + запись + выполнение
  5 = r-x (4+0+1)  → группа: чтение + выполнение
  5 = r-x (4+0+1)  → остальные: чтение + выполнение
```

| Частые права | Значение | Типичное применение |
|---------|------|---------|
| `644` | rw-r--r-- | Обычный файл (владелец может писать, остальные только читают) |
| `755` | rwxr-xr-x | Исполняемый файл/каталог |
| `600` | rw------- | Приватный файл (например, SSH-ключ) |
| `777` | rwxrwxrwx | Все могут читать/писать/выполнять (опасно, избегайте использования) |

### sudo: временное получение суперправ

Права обычного пользователя ограничены, некоторые операции требуют прав root. `sudo` позволяет временно выполнить команду от имени root:

```bash
# 普通用户无法修改系统配置
$ vim /etc/nginx/nginx.conf
# Permission denied

# 用 sudo 临时提权
$ sudo vim /etc/nginx/nginx.conf
# 输入你的密码后可以编辑

# 切换到 root 用户（谨慎使用）
$ sudo su -
```

::: warning Принцип минимальных привилегий
Никогда не решайте проблемы прав через `chmod 777` — это всё равно что снять дверной замок. Правильный подход — разобраться, кому какие права нужны, и точно их выдать. Так же не работайте постоянно от имени root, используйте `sudo` только при необходимости.
:::

## 4. Основы Shell

Shell — это «переводчик» между вами и ядром Linux. Вы вводите команду, Shell интерпретирует её и передаёт ядру на выполнение. Самые распространённые Shell — **Bash** (по умолчанию в большинстве дистрибутивов Linux) и **Zsh** (по умолчанию в macOS).

### Каналы и перенаправление

Это две самые мощные возможности Shell:

| Символ | Название | Назначение | Пример |
|------|------|------|------|
| `|` | Канал | Передаёт вывод предыдущей команды на вход следующей | `cat log | grep ERROR` |
| `>` | Перенаправление вывода | Записывает вывод в файл (перезапись) | `echo "hello" > file.txt` |
| `>>` | Перенаправление с дозаписью | Дописывает вывод в конец файла | `echo "world" >> file.txt` |
| `<` | Перенаправление ввода | Читает ввод из файла | `wc -l < file.txt` |
| `2>` | Перенаправление ошибок | Записывает сообщения об ошибках в файл | `cmd 2> error.log` |
| `2>&1` | Объединение вывода | Объединяет ошибки и обычный вывод | `cmd > all.log 2>&1` |

### Переменные окружения

Переменные окружения — это «глобальная конфигурация» в Shell, влияющая на поведение команд:

```bash
# 查看所有环境变量
env

# 查看某个变量
echo $PATH
echo $HOME

# 临时设置（只在当前 Shell 有效）
export API_KEY="abc123"

# 永久设置（写入配置文件）
echo 'export API_KEY="abc123"' >> ~/.bashrc
source ~/.bashrc   # 让配置立即生效
```

| Частые переменные | Значение | Пример значения |
|---------|------|--------|
| `$PATH` | Путь поиска команд | `/usr/local/bin:/usr/bin:/bin` |
| `$HOME` | Домашний каталог пользователя | `/home/alice` |
| `$USER` | Имя текущего пользователя | `alice` |
| `$PWD` | Текущий рабочий каталог | `/var/log` |
| `$SHELL` | Используемый сейчас Shell | `/bin/bash` |

### Введение в Shell-скрипты

Если записать несколько команд в один файл — это и есть Shell-скрипт. Это отправная точка автоматизации эксплуатации:

```bash
#!/bin/bash
# deploy.sh - 简单的部署脚本

APP_DIR="/opt/myapp"
LOG_FILE="/var/log/deploy.log"

echo "$(date) - 开始部署..." >> $LOG_FILE

# 拉取最新代码
cd $APP_DIR && git pull origin main

# 安装依赖
npm install --production

# 重启服务
pm2 restart myapp

echo "$(date) - 部署完成" >> $LOG_FILE
```

```bash
# 给脚本执行权限并运行
chmod +x deploy.sh
./deploy.sh
```

::: tip Приёмы отладки скриптов
Добавьте в начало скрипта `set -ex`: `-e` заставляет скрипт немедленно завершаться при ошибке (а не продолжать выполнение), `-x` печатает каждую выполняемую команду (удобно для поиска проблем). Эти две опции — практически стандарт для продакшен-скриптов.
:::

## 5. Практические сценарии

Теория изучена, рассмотрим несколько практических сценариев, которые чаще всего встречаются в разработке.

### 5.1 Анализ логов

Если с сервисом проблема, первая реакция — смотреть логи. Ниже распространённые приёмы анализа логов:

```bash
# 1. 实时跟踪日志（最常用）
tail -f /var/log/app/error.log

# 2. 搜索特定时间段的错误
grep "2024-01-15 14:" error.log | grep "ERROR"

# 3. 统计每小时的错误数量
grep "ERROR" app.log | awk '{print substr($1,1,13)}' | uniq -c

# 4. 查看最近 100 行日志
tail -100 app.log

# 5. 在多个日志文件中搜索
grep -r "OutOfMemory" /var/log/app/
```

### 5.2 Диагностика процессов

Зависание приложения, скачок CPU, утечка памяти — все эти проблемы требуют начинать с процессов:

```bash
# 查看 CPU 占用最高的进程
ps aux --sort=-%cpu | head -10

# 查看内存占用最高的进程
ps aux --sort=-%mem | head -10

# 查找特定进程
ps aux | grep "node"

# 查看进程的详细信息（包括线程）
top -Hp <PID>

# 查看进程打开的文件
lsof -p <PID>

# 优雅终止进程（SIGTERM）
kill <PID>

# 强制终止（SIGKILL，最后手段）
kill -9 <PID>
```

### 5.3 Сетевая диагностика

Не получается подключиться к сервису? Сначала выясните, проблема в сети или в приложении:

```bash
# 测试目标是否可达
ping -c 4 google.com

# 检查端口是否开放
telnet db-server 3306
# 或者用 nc
nc -zv db-server 3306

# 查看本机监听的端口
ss -tlnp
# 或
netstat -tlnp

# DNS 解析检查
dig api.example.com
nslookup api.example.com

# 测试 HTTP 接口
curl -v http://localhost:3000/health

# 查看网络连接状态统计
ss -s
```

### 5.4 Диагностика дискового пространства

Заполнение диска — один из самых частых сбоев на продакшене:

```bash
# 查看各分区使用情况
df -h

# 找出占用空间最大的目录
du -sh /* 2>/dev/null | sort -rh | head -10

# 进一步定位大目录
du -sh /var/log/* | sort -rh | head -10

# 查找大文件（>100MB）
find / -type f -size +100M 2>/dev/null | head -20

# 清理常见的空间占用
# 清理旧日志
sudo journalctl --vacuum-size=500M
# 清理 Docker 无用镜像
docker system prune -a
```

::: tip Поговорка диагностики на продакшене
**«Сначала логи, потом процессы, затем сеть, в конце диск».** 90% проблем на продакшене можно локализовать этими четырьмя шагами. Когда это войдёт в привычку, эффективность диагностики значительно вырастет.
:::

## Заключение

Linux — обязательный навык разработчика, и владения основами достаточно для решения большинства повседневных задач разработки и эксплуатации.

Вспомним ключевые моменты этой главы:

1. **Всё есть файл**: Linux через файловую абстракцию унифицирует способ доступа к оборудованию, процессам, сети и другим ресурсам
2. **Комбинирование команд**: отдельная команда проста по функциям, настоящая сила раскрывается лишь при комбинировании через канал `|`
3. **Модель прав**: Owner/Group/Others × Read/Write/Execute, быстрая настройка через числа (например, 755)
4. **Основы Shell**: каналы, перенаправление, переменные окружения, скрипты — краеугольный камень автоматизации
5. **Практическая диагностика**: логи → процессы → сеть → диск, четыре шага для локализации большинства проблем на продакшене
