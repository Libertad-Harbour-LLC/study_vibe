# Руководство по браузерному отладчику (DevTools)

::: tip 💡 Ключевая роль
Инструменты разработчика в браузере (DevTools) — это «рентгеновский аппарат» и «операционный стол» фронтенд-разработки. Они позволяют вам видеть насквозь скелет (HTML), кожу (CSS) и нервную систему (JavaScript) веб-страницы, а также изменять и отлаживать их в реальном времени.
:::

## 1. Что такое DevTools?

**DevTools** — это набор встроенных инструментов для веб-разработки и отладки в современных браузерах (Chrome, Edge, Firefox, Safari и др.). Для разработчика они ближе к «истине», чем редактор кода, потому что **показывают, как код реально работает в браузере**.

**Как открыть DevTools?**

- **Горячие клавиши**: `F12` или `Ctrl + Shift + I` (Mac: `Cmd + Option + I`)
- **Мышь**: **щёлкните правой кнопкой** на любом элементе страницы и выберите **«Просмотреть код (Inspect)»**.
- **Меню**: меню в правом верхнем углу браузера -> Дополнительные инструменты -> Инструменты разработчика.

### 2.2 Практический вызов: изменение текста реальной страницы

Раз уж вы освоили приём изменения стилей, давайте теперь сделаем что-то поинтереснее — **изменим прямо ту страницу, которую вы сейчас видите!**

1.  **Откройте настоящие DevTools**: нажмите `F12` (или щёлкните правой кнопкой по этой строке текста -> выберите «Просмотреть код»).
2.  **Найдите элемент**: в панели Elements вы увидите подсвеченную строку кода — это и есть текст, по которому вы только что кликнули.
3.  **Измените содержимое**: **дважды кликните** по чёрному тексту в этой строке кода, замените его на «**Я хакер!**» и нажмите Enter.
4.  **Узрите чудо**: смотрите! Текст на странице изменился, не так ли?

::: info 🤔 Почему после обновления всё пропадает?
Возможно, вы заметите, что после обновления страницы все изменения исчезают, и страница возвращается к прежнему виду.

Это потому, что изменения в DevTools происходят только в **локальной памяти вашего браузера**.

- Когда вы открываете страницу, браузер загружает HTML-код с **удалённого сервера** и рендерит его локально.
- Вы изменяете лишь **локальную копию**, у вас нет прав изменять **исходный код** на сервере.
- Поэтому при каждом обновлении браузер заново скачивает с сервера самый свежий (неизменённый) код, и всё восстанавливается.
  :::

## 3. Подробный разбор основных панелей

### 3.1 Elements (панель элементов)

<ClientOnly>
  <DevToolsElementsDemo />
</ClientOnly>

**Назначение**: просмотр и редактирование HTML и CSS страницы в реальном времени.

- **Слева (дерево DOM)**: отображает HTML-структуру страницы. Вы можете дважды кликнуть по тегу или тексту для изменения и даже перетаскивать узлы, меняя их положение.
- **Справа (Styles)**: отображает CSS-стили выбранного элемента. Можно включать/выключать стили, наблюдая изменения, или напрямую менять значения (например, цвет, отступы).
- **Сценарии использования**:
  - «Почему эта кнопка не выровнена?» -> проверьте CSS-стили.
  - «Хочу попробовать сделать заголовок красным — будет ли красиво?» -> прямо в Styles измените `color: red`.

### 3.2 Console (панель консоли)

<ClientOnly>
  <DevToolsConsoleDemo />
</ClientOnly>

**Назначение**: просмотр логов, выполнение кода JavaScript.

- **Вывод логов**: сообщения `console.log()`, предупреждения (жёлтые) и ошибки (красные), возникающие при работе страницы, отображаются здесь.
- **Интерактивная среда**: вы можете ввести любой JS-код и сразу его выполнить. Например, ввод `alert('Hello')` вызовет всплывающее окно, а ввод `document.body.style.background = 'red'` сделает фон красным.
- **Сценарии использования**:
  - «Почему кнопка не реагирует на клик?» -> проверьте, нет ли красных сообщений об ошибках.
  - «Проверить возвращаемое значение JS-функции.» -> запустите тест прямо в консоли.

### 3.3 Network (панель сети)

<ClientOnly>
  <DevToolsNetworkDemo />
</ClientOnly>

**Назначение**: мониторинг всех сетевых запросов.

- **Список**: показывает все загруженные ресурсы (HTML, CSS, JS, изображения, запросы к API).
- **Подробности**: при клике по любой строке запроса справа выезжает панель деталей:
  - **Headers (заголовки)**: просмотр заголовков запроса и ответа (например, `Content-Type`).
  - **Response (ответ)**: просмотр исходных данных, вернувшихся с сервера (JSON, HTML-код и т. д.).
  - **Preview (предпросмотр)**: просмотр содержимого ответа в более удобочитаемом формате.
- **Ключевые показатели**:
  - **Status**: код состояния (200 — успех, 404 — не найдено, 500 — ошибка сервера).
  - **Type**: тип ресурса (fetch/xhr означает запрос к API).
  - **Time**: время загрузки.
- **Сценарии использования**:
  - «API не упал?» -> проверьте, не красный ли запрос с кодом 500.
  - «Почему страница загружается так медленно?» -> найдите, какое изображение или файл грузится дольше всего.

### 3.4 Sources (панель исходного кода)

<ClientOnly>
  <DevToolsSourcesDemo />
</ClientOnly>

**Назначение**: просмотр исходного кода, отладка JavaScript.

- **Отладка по точкам останова**: клик по номеру строки устанавливает «точку останова (Breakpoint)». Когда выполнение кода доходит до этой строки, оно **приостанавливается**, давая вам возможность посмотреть текущие значения переменных и выполнять код пошагово.
- **Сценарии использования**:
  - «Где в логике кода ошибка?» -> поставьте точку останова и шаг за шагом следите за выполнением, проверяя, соответствуют ли значения переменных ожиданиям.

### 3.5 Application (панель приложения)

<ClientOnly>
  <DevToolsApplicationDemo />
</ClientOnly>

**Назначение**: просмотр и управление хранилищем браузера.

- **Storage**:
  - **Local Storage**: данные постоянного хранения.
  - **Session Storage**: хранилище уровня сессии (исчезает при закрытии вкладки).
  - **Cookies**: небольшие текстовые данные, используемые для аутентификации и т. п.
- **Сценарии использования**:
  - «Очистить состояние входа» -> удалите token из Cookies или Local Storage.
  - «Посмотреть кэшированные данные» -> проверьте, что хранится в Local Storage.

## 4. Практические приёмы

1.  **Отладка в режиме телефона**: кликните по «иконке телефона» 📱 в левом верхнем углу DevTools, чтобы эмулировать размеры экранов разных моделей телефонов (iPhone, Pixel и др.) и протестировать адаптивность страницы.
2.  **Принудительное состояние**: в панели Elements щёлкните правой кнопкой по элементу, выберите `Force state` -> `:hover`, чтобы принудительно удерживать элемент в состоянии наведения — удобно для отладки стилей при наведении мыши.
3.  **Скриншот узла**: выберите узел в панели Elements, нажмите `Ctrl + Shift + P` (Mac: `Cmd + Shift + P`), чтобы открыть командное меню, введите `screenshot`, выберите `Capture node screenshot` — и этот DOM-узел будет сохранён как изображение.

::: warning ⚠️ Внимание
Все изменения в DevTools (изменения HTML, CSS, JS) являются **временными** и действуют только на текущей странице браузера. После обновления страницы все изменения теряются. Чтобы изменения сохранились навсегда, нужно изменить файлы исходного кода.
:::
