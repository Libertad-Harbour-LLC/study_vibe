## 0. Введение: что же это за `localhost:5173`, который мы видим каждый день?

<DevServerFlowDemo />

Повседневная работа каждого разработчика не обходится без этой строки вывода:

```
➜  Local:   http://localhost:5173/
```

Но задумывались ли вы, что в этой коротенькой строке скрыто сразу несколько ключевых понятий:

- **http://** → протокол связи (на каком языке вести диалог)
- **localhost** → целевой адрес (к кому обращаться)
- **:5173** → номер порта (когда нашли, в какую дверь стучать)

Разобравшись в этих трёх вещах, вы поймёте 90% сетевых проблем среды разработки. Дальше мы разберём каждую по очереди.

## 1. Что такое порт? (IP — это здание, порт — номер комнаты)

### 1.1 Интуитивная аналогия

Представьте, что сервер — это здание:

- **IP-адрес** (например, `192.168.1.100`) — это адрес здания, он говорит вам, «к какому зданию идти».
- **Номер порта** (например, `:80`) — это номер комнаты в здании, он говорит, «в какую комнату войти».

В одном здании могут одновременно быть ресторан (комната 80), кофейня (комната 443), офис (комната 22). Точно так же на одном компьютере могут одновременно работать веб-сервер, база данных, SSH-служба, каждая занимая свой порт.

### 1.2 Диапазон значений номеров портов

Номер порта — это целое число от **0 до 65535** (всего 65536). Это множество портов делится на три диапазона:

| Диапазон | Значения | Назначение | Пример |
| :--- | :--- | :--- | :--- |
| **Системные порты** | 0 – 1023 | Зарезервированы для стандартных протоколов, обычные пользователи не могут произвольно их занимать | 80 (HTTP), 443 (HTTPS), 22 (SSH) |
| **Зарегистрированные порты** | 1024 – 49151 | Используются для регистрации распространёнными приложениями | 3306 (MySQL), 5432 (PostgreSQL), 6379 (Redis) |
| **Динамические порты** | 49152 – 65535 | Временно назначаются операционной системой | при отправке запроса браузером система случайно назначает исходный порт |

> Почему ваш сервер разработки любит использовать 3000, 5173, 8080? Потому что все они находятся в диапазоне «зарегистрированных портов» — для прослушивания не нужны права администратора, и при этом они не очень склонны конфликтовать с системными службами.

## 2. Что такое localhost? (сам ищет сам себя)

### 2.1 Ключевое понятие «петли»

`localhost` — это особое доменное имя, которое всегда указывает на **ваш собственный компьютер**.

Когда вы вводите в браузере `http://localhost:3000`, происходит следующее:

1. Браузер спрашивает операционную систему: «Какой IP у `localhost`?»
2. Операционная система прямо отвечает: «`127.0.0.1`» (не нужно выходить в сеть и запрашивать DNS)
3. Пакет данных отправляется на `127.0.0.1`, но **на самом деле не покидает машину**
4. Операционная система через «петлевой интерфейс (loopback interface)» **разворачивает** пакет обратно
5. Программа, слушающая на порту 3000, получает запрос и возвращает ответ

**Весь процесс не проходит через сетевой кабель, не проходит через маршрутизатор, не требует выхода в сеть.**

### 2.2 `localhost` vs `127.0.0.1` vs `0.0.0.0`

Эти три понятия часто путают, но их смысл совершенно разный:

| Запись | Значение | Кто может обращаться |
| :--- | :--- | :--- |
| `localhost` / `127.0.0.1` | Петлевой адрес, только локальная машина | Только ваш компьютер |
| `0.0.0.0` | Прослушивание всех сетевых интерфейсов | Локальная машина + другие устройства в локальной сети |
| `192.168.x.x` | IP локальной сети | Устройства в локальной сети |

**Реальный сценарий**:

```bash
# Доступ только у вас (безопасно, подходит для разработки)
npm run dev -- --host localhost

# Доступ и с телефона (подходит для отладки на мобильных)
npm run dev -- --host 0.0.0.0
```

> Многие фреймворки (например, Vite, Next.js) по умолчанию слушают `localhost`, поэтому ваш телефон не сможет получить доступ, даже будучи подключённым к тому же Wi-Fi. Хотите отлаживать на телефоне? Просто добавьте параметр `--host`.

## 3. Конфликт портов: самая частая проблема среды разработки

### 3.1 Почему возникает конфликт?

**Один порт в один момент времени может слушать только одна программа.** Это как комната, в которой может жить только одна семья.

Если вы попытаетесь запустить вторую службу на том же порту, вы увидите эту классическую ошибку:

```
Error: listen EADDRINUSE :::3000
```

В переводе на человеческий язык это означает: **«В комнате 3000 уже кто-то живёт, вам не войти!»**

Частые сценарии конфликта:
- Прошлый сервер разработки не был корректно остановлен и всё ещё работает в фоне
- Два разных проекта используют один и тот же порт по умолчанию
- Какая-то системная служба уже заняла нужный вам порт

### 3.2 Диагностика и решение

При конфликте портов процедура диагностики весьма устойчива:

**macOS / Linux:**
```bash
# Шаг первый: смотрим, кто занимает порт 3000
lsof -i :3000

# Шаг второй: получив PID, принудительно завершаем
kill -9 <PID>
```

**Windows:**
```bash
# Шаг первый: смотрим, кто занимает порт 3000
netstat -ano | findstr :3000

# Шаг второй: завершаем процесс
taskkill /PID <PID> /F
```

> Многие современные фреймворки (Vite, Create React App и др.) при конфликте портов автоматически спрашивают: «Сменить порт?». Но понимание базовых принципов поможет вам быстрее разобраться с теми сложными случаями, в которых фреймворк бессилен.

## 4. «Политика одного источника» и кросс-домен в разработке

### 4.1 Что такое «источник»?

У браузера есть механизм безопасности под названием **политика одного источника (Same-Origin Policy)**: только при полном совпадении трёх компонентов — **протокола, доменного имени и порта** — считается, что это «один источник».

| Адрес A | Адрес B | Один источник? | Причина |
| :--- | :--- | :--- | :--- |
| `http://localhost:5173` | `http://localhost:5173/about` | ✅ Один источник | Протокол, домен и порт одинаковые |
| `http://localhost:5173` | `http://localhost:3000` | ❌ Разные источники | **Порт разный** (5173 vs 3000) |
| `http://localhost:5173` | `https://localhost:5173` | ❌ Разные источники | **Протокол разный** (http vs https) |

### 4.2 Почему при разделении фронтенда и бэкенда неизбежно возникает кросс-домен?

Когда архитектура вашего проекта такая:

```
Фронтенд (Vite)  →  http://localhost:5173
Бэкенд (Express) →  http://localhost:3000
```

Страница фронтенда загружается с `:5173`, а затем через `fetch('/api/users')` обращается к API на `:3000` — **порты разные, срабатывает ограничение кросс-домена!**

**Два распространённых решения:**

**Решение первое: настроить CORS на бэкенде**
```javascript
// Бэкенд Express
app.use(cors({ origin: 'http://localhost:5173' }))
```

**Решение второе: настроить прокси на фронтенде (рекомендуется)**
```javascript
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': 'http://localhost:3000'
    }
  }
}
```

Принцип работы прокси: заставить сервер разработки Vite «пересылать» запросы за вас. Браузер считает, что общается с `:5173` (один источник), а на самом деле Vite за кулисами незаметно перенаправляет запрос на `:3000`.

## 6. Таблица соответствия терминов

| Английский термин | Русское соответствие | Пояснение |
| :--- | :--- | :--- |
| **Port** | Порт | Число от 0 до 65535, используется для различения разных сетевых служб на одной машине. Каждая служба «слушает» один порт, ожидая подключения клиента. |
| **localhost** | Локальный хост | Особое доменное имя, всегда указывающее на локальную машину (127.0.0.1). Используется для доступа к службам, работающим на локальной машине, без выхода в сеть. |
| **Loopback Interface** | Петлевой интерфейс | Виртуальный сетевой интерфейс операционной системы. Пакеты, отправленные на 127.0.0.1, не покидают машину, а «разворачиваются» обратно через этот интерфейс. |
| **EADDRINUSE** | Адрес уже используется | Ошибка Node.js / операционной системы, означающая, что порт, который вы хотите слушать, уже занят другой программой. |
| **CORS** | Совместное использование ресурсов между источниками | Механизм безопасности браузера. Когда страница фронтенда пытается обратиться к API другого источника (отличается протокол/домен/порт), требуется явное разрешение бэкенда. |
| **Same-Origin Policy** | Политика одного источника | Основа безопасности браузера: разрешает свободное взаимодействие только запросам с одним протоколом, доменом и портом, блокируя кросс-доменное чтение данных. |
| **Proxy** | Прокси | В среде разработки прокси-сервер вместо браузера пересылает запросы бэкенду, обходя ограничение одного источника. |
| **0.0.0.0** | Все интерфейсы | Когда служба слушает 0.0.0.0, это означает, что она принимает соединения с любого сетевого интерфейса (локальная машина, локальная сеть и т. д.). |
| **Well-known Ports** | Общеизвестные порты | Общее название портов 0–1023, зарезервированных для стандартных протоколов вроде HTTP (80), HTTPS (443), SSH (22). |
| **PID** | Идентификатор процесса | Уникальный номер, который операционная система назначает каждой запущенной программе, используется для управления и завершения процессов. |
| **lsof** | Список открытых файлов | Команда macOS/Linux для просмотра, какой процесс занимает определённый порт (`lsof -i :номер_порта`). |
| **HMR** | Горячая замена модулей | Функция сервера разработки: после изменения кода браузер автоматически обновляется без ручного перезагрузки страницы. На низком уровне браузер уведомляется через WebSocket. |

## Итог

Порт и localhost — самые базовые и часто встречающиеся понятия среды разработки:

- **Порт** = «номер двери» (0–65535), различающий разные службы на одной машине
- **localhost** = особый адрес «сам ищет сам себя» (127.0.0.1), данные не покидают машину
- Суть **конфликта портов** в том, что «на одной двери может висеть только одна табличка»
- Суть **кросс-домена** в том, что «разный порт = разный источник», и для решения нужен CORS или прокси

Запомните эти четыре фразы — и большинство сетевых проблем, с которыми вы столкнётесь в среде разработки, вы сможете быстро локализовать.
