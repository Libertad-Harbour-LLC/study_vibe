# SSH и аутентификация по ключам

> 💡 **Руководство по обучению**: каждый раз при `git push` вводите пароль? При подключении к серверу постоянно видите «Permission denied»? В этой главе за 5 минут разберёмся в принципах аутентификации по SSH-ключам и в том, как одним действием настроить вход без пароля на GitHub и сервер.

---

## 0. Вы наверняка сталкивались с такими ситуациями

- При `git push` снова и снова всплывает окно ввода пароля — до невозможности утомительно
- SSH-подключение к серверу не удаётся, и непонятно, что такое `id_rsa` и `id_ed25519`
- Слышали про «публичный ключ» и «приватный ключ», но не понимаете, какой отдавать другим, а какой оставлять себе

**Главное противоречие**: пароль небезопасен и неудобен. SSH-ключи — это решение, которое одновременно даёт и безопасность, и удобство.

## 2. Асимметричное шифрование: публичный и приватный ключ

SSH-ключи основаны на **асимметричном шифровании**: за один раз создаются два ключа:

| | Приватный ключ (Private Key) | Публичный ключ (Public Key) |
|---|---|---|
| **Где хранится** | Ваш компьютер `~/.ssh/id_ed25519` | Сервер / GitHub |
| **Можно ли отдавать другим** | ❌ Ни в коем случае | ✅ Можно свободно |
| **Назначение** | Подпись (подтверждение личности) | Проверка подписи (верификация личности) |
| **Аналогия** | Ключ | Замок |

### Распространённые типы ключей

| Тип | Команда | Рекомендуемость | Описание |
|---|---|---|---|
| **Ed25519** | `ssh-keygen -t ed25519` | ⭐⭐⭐ | Самый новый, быстрый и безопасный |
| **RSA** | `ssh-keygen -t rsa -b 4096` | ⭐⭐ | Хорошая совместимость, но медленнее |
| **ECDSA** | `ssh-keygen -t ecdsa` | ⭐ | Как правило, не рекомендуется |

## 3. Практика: генерация и настройка SSH-ключа

### 3.1 Генерация пары ключей

```bash
ssh-keygen -t ed25519 -C "your@email.com"
```

После выполнения появятся подсказки:
- **Путь к файлу**: просто нажмите Enter, чтобы использовать путь по умолчанию `~/.ssh/id_ed25519`
- **Парольная фраза**: можно задать дополнительную защиту (можно и оставить пустой)

### 3.2 Добавление публичного ключа на GitHub

```bash
# 1. Копируем содержимое публичного ключа
cat ~/.ssh/id_ed25519.pub | pbcopy  # macOS
cat ~/.ssh/id_ed25519.pub | xclip   # Linux

# 2. Открываем GitHub → Settings → SSH and GPG keys → New SSH key
# 3. Вставляем публичный ключ, сохраняем

# 4. Проверяем подключение
ssh -T git@github.com
# При успехе увидите: Hi username! You've been authenticated...
```

### 3.3 Добавление публичного ключа на сервер

```bash
# Способ 1: ssh-copy-id (рекомендуется)
ssh-copy-id user@your-server

# Способ 2: копирование вручную
cat ~/.ssh/id_ed25519.pub | ssh user@server "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

## 4. SSH Config: прощаемся с длинными командами

Настройте псевдонимы в `~/.ssh/config` — один раз настроили и пользуетесь всю жизнь:

```
Host dev
  HostName 192.168.1.100
  User deploy
  IdentityFile ~/.ssh/id_ed25519

Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519
```

Эффект после настройки:

| Было | Стало |
|---|---|
| `ssh -i ~/.ssh/id_ed25519 deploy@192.168.1.100` | `ssh dev` |
| Каждый раз нужно помнить IP и имя пользователя | Достаточно помнить один псевдоним |

## 5. Устранение распространённых проблем

| Проблема | Причина | Решение |
|---|---|---|
| `Permission denied (publickey)` | Публичный ключ не добавлен на сервер | `ssh-copy-id user@server` |
| `WARNING: UNPROTECTED PRIVATE KEY FILE` | Слишком широкие права на файл приватного ключа | `chmod 600 ~/.ssh/id_ed25519` |
| `Could not resolve hostname` | Ошибка в настройке SSH Config | Проверьте формат `~/.ssh/config` |
| GitHub всё равно требует пароль | Используется HTTPS, а не SSH | Перейдите на `git@github.com:user/repo.git` |

## 6. Итог

::: tip 📚 Ключевые моменты
1. **Ключ > пароль**: приватный ключ никогда не передаётся, он намного безопаснее пароля
2. **Рекомендуется Ed25519**: самый современный алгоритм ключей, высокая скорость и безопасность
3. **Публичный ключ можно отдавать свободно, приватный — никогда не разглашайте**: запомните это железное правило
4. **SSH Config**: настройте псевдоним один раз, а потом подключайтесь одной командой `ssh псевдоним`
5. **GitHub/GitLab**: после добавления публичного ключа для `git push/pull` больше не нужно вводить пароль
:::
