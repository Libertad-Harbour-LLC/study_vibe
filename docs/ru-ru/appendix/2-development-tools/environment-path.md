# Переменные окружения и PATH

> 💡 **Руководство по обучению**: каждый раз, когда вы вводите в терминале `git` или `python`, системе нужно найти, где находится эта программа. Каждый раз, когда ваш код вызывает API большой модели, программе нужно знать, какой ключ использовать. За обоими этими вещами стоит один и тот же механизм — **переменные окружения**.

---

## 0. У каждой программы при себе есть набор настроек

У каждой запущенной программы есть набор настроек вида «ключ=значение», который называется **переменными окружения**. Программа может в любой момент прочитать эти настройки, чтобы понять текущее окружение выполнения.

## 1. PATH: как Shell находит введённую вами команду

`PATH` — это особая переменная окружения, в которой хранится цепочка путей к каталогам (разделённых двоеточием). Когда вы вводите `git`, Shell по порядку проходит по этим каталогам, заходя в каждый и ища исполняемый файл с именем `git` — и сразу останавливается, найдя первый.

```bash
$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

Выберите команду и понаблюдайте за тем, как Shell ищет её по каталогам:

<PathSearchDemo />

**Три ключевые закономерности**:
- Чем раньше каталог стоит в PATH, тем выше его приоритет
- Найдя первый, поиск останавливается и дальше не продолжается
- Если ни в одном каталоге нет → `command not found`

## 2. Почему после установки инструмента нужно перезапускать терминал?

При установке инструментов вроде nvm, Homebrew, conda установочный скрипт автоматически добавляет строку в `~/.zshrc`, добавляя свой каталог в PATH:

```bash
# Содержимое, автоматически записанное установочным скриптом (пример)
export PATH="/usr/local/opt/python@3.12/bin:$PATH"
```

Эта строка выполняется только **при запуске нового Shell**. Уже открытые окна терминала на это не реагируют, поэтому:

```bash
# Можно применить сразу без перезапуска
source ~/.zshrc
```

**Частые случаи в инструментах для AI-разработки**:

```bash
# После установки Ollama / pipx выдаётся command not found
which ollama          # Проверяем реальное место установки

# Путь к CLI-инструментам, установленным через pip (добавляем в PATH)
# macOS: ~/Library/Python/3.x/bin
# Linux: ~/.local/bin
export PATH="$PATH:$HOME/.local/bin"

# Для установки инструментов командной строки рекомендуется pipx, он автоматически управляет PATH
pipx install aider-chat
```

## 3. Область видимости переменных: кто может увидеть эту переменную?

Переменные окружения не транслируются всем программам — каждый процесс держит **свою собственную копию**, унаследованную от родительского процесса; изменение своей копии не влияет на родительский процесс.

## 4. export: определяет, сможет ли дочерний процесс прочитать эту переменную

При установке переменной добавлять `export` или нет — это две совершенно разные вещи:

<EnvExportDemo />

Чтобы переменная навсегда сохранялась между сессиями, запишите `export` в файл конфигурации:

```bash
# macOS (zsh)
echo 'export MY_VAR="value"' >> ~/.zshrc
source ~/.zshrc       # Применяется сразу, без перезапуска терминала

# Linux (bash)
echo 'export MY_VAR="value"' >> ~/.bashrc
source ~/.bashrc
```

## 6. Локальная разработка: храните ключи в файле .env

## 8. Практическое устранение ошибок

### `command not found`

```bash
# Шаг 1: проверяем, есть ли в PATH
which python3         # Если есть вывод — значит, найдено

# Шаг 2: находим реальное расположение программы (macOS)
brew list python | grep bin

# Шаг 3: добавляем каталог в PATH
export PATH="/найденный/путь:$PATH"
source ~/.zshrc       # После записи в файл конфигурации не забудьте source
```

### Установлено две версии, используется не та, которую я хочу

```bash
which python
# /usr/bin/python ← старая системная версия, стоит раньше в PATH

# Помещаем каталог новой версии в самое начало PATH
export PATH="/usr/local/bin:$PATH"

which python
# /usr/local/bin/python ← новая версия, теперь приоритетна
```

### Переменная явно задана, а программа её не видит

| Причина | Решение |
|:---|:---|
| Забыли `export` | Добавьте `export` и попробуйте снова |
| Изменили `~/.zshrc`, но не применилось | `source ~/.zshrc` |
| Использовали `.env`, но не установили dotenv | `pip install python-dotenv` / `npm install dotenv` |
| На сервере действует только в SSH-сессии | Перейдите на systemd `EnvironmentFile` |

## Быстрый справочник терминов

| Термин | Значение |
|:---|:---|
| **PATH** | Хранит список каталогов, в которых Shell ищет исполняемые файлы; разделён двоеточием, порядок определяет приоритет |
| **export** | Помечает переменную как наследуемую, дочерний процесс при запуске автоматически получает её копию |
| **source** | Повторно выполняет файл конфигурации в текущем Shell, чтобы изменения вступили в силу немедленно |
| **which** | Показывает путь к исполняемому файлу для данной команды (результат поиска по PATH) |
| **.env** | Локальный файл конфигурации проекта, хранит ключи для разработки, обязательно добавляется в `.gitignore` |
| **.env.example** | Шаблон с полными именами переменных и пустыми значениями, его можно безопасно коммитить в Git |
| **chmod 600** | Права на файл: чтение и запись только для владельца, подходит для защиты файлов с ключами |
| **Secret Scanner** | GitHub и другие платформы автоматически сканируют утечки ключей и при обнаружении уведомляют поставщика для отзыва |
