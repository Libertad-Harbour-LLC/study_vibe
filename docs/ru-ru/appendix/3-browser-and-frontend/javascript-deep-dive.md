# Подробное руководство по JavaScript

::: tip Предисловие
Вы уже научились HTML и CSS и можете делать красивые веб-страницы. Но вы могли заметить: нажимаешь на кнопку — ничего не происходит, заполнил форму — отправить не получается, страница похожа на «статичную» картинку.

Именно поэтому нам нужен JavaScript — он «оживляет» страницу. Нажатие на кнопку раскрывает меню, ввод текста запускает поиск в реальном времени, прокрутка страницы подгружает новый контент… все эти интерактивные эффекты обеспечивает JavaScript.

В vibecoding большую часть кода за вас напишет ИИ. Но вы как минимум должны понимать, что делает код, иначе вы не заметите, если ИИ ошибётся. Прочитав эту статью, вы сможете:

- Понимать, что делает код, написанный ИИ
- Видеть, где в коде есть проблема
- Чётко объяснять ИИ, что нужно исправить
:::

**Чему научит вас эта статья?**

| Глава | Содержание | Что вы сможете после изучения |
|-----|------|-----------|
| **Глава 1** | Что такое JavaScript | Понять, какую роль он играет на веб-странице |
| **Глава 2** | Данные и переменные | Узнать, как программа хранит данные и как их использует |
| **Глава 3** | Функции и логика | Понимать условия, циклы и логику повторного использования в коде |

| **Глава 5** | Практические приёмы | Как читать код от ИИ и как формулировать ошибки |

Каждая глава начинается с того, чтобы вы могли «распознавать код», вам не нужно уметь писать его вручную. Встретив непонятный код, просто возвращайтесь сюда за справкой.

## 1. Что такое JavaScript

::: tip 🤔 Ключевой вопрос
**Почему веб-странице нужен JavaScript?** HTML и CSS уже позволяют странице иметь содержимое и стиль, зачем же изучать ещё один язык?
:::

### 1.1 От «статичной страницы» к «динамическому приложению»

<div style="display: flex; gap: 20px; margin: 20px 0;">
<div style="flex: 1; padding: 16px; border: 1px solid #e4e7ed; border-radius: 12px;">

**📄 Страница без JavaScript**
- Содержимое фиксировано, без интерактивности
- Нажатие на кнопку ничего не делает
- Форму нельзя отправить
- Страница не обновляется автоматически

*Как бумажный плакат — на него можно только смотреть*

</div>
<div style="flex: 1; padding: 16px; border: 1px solid #e4e7ed; border-radius: 12px;">

**🚀 Страница с JavaScript**
- Нажатие на кнопку раскрывает меню
- Ввод текста запускает поиск в реальном времени
- Прокрутка автоматически подгружает контент
- Данные обновляются в реальном времени

*Как настоящее приложение*

</div>
</div>

**Поймём отношение трёх технологий одной фразой:**

| Технология | Метафора | Назначение |
|------|------|------|
| **HTML** | Скелет | Определяет структуру и содержимое страницы |
| **CSS** | Кожа | Определяет внешний вид и стиль страницы |
| **JavaScript** | Мышцы и нервная система | Позволяют странице реагировать, взаимодействовать и «думать» |

### 1.2 Почему в vibecoding тоже нужно понимать JavaScript?

::: warning История о ловушке начинающего разработчика JS
Один разработчик, только начавший изучать JavaScript, сделал с помощью ИИ приложение-«счётчик»: нажимаешь на кнопку — число увеличивается на 1. Сгенерированный ИИ код работал нормально.

Но он захотел сделать «увеличение на 2» и сказал ИИ: «Пусть каждое нажатие добавляет 2». ИИ изменил код, но число по-прежнему увеличивалось только на 1.

Он спросил ИИ, почему нет эффекта, ИИ что-то объяснил, но разработчик не понимал, что значит `count = count + 1` в коде, и не знал, изменил ли ИИ именно это место. Ему оставалось только снова и снова повторять «прибавление 2 не работает», ИИ переписывал код по несколько раз: где-то менял начальное значение на 2, где-то добавлял 2 в совершенно не связанном месте.

В конце концов он прочитал в главе 2 понятие «переменная» и понял, что `count = count + 1` — это прибавление 1 к значению count и сохранение результата обратно. Затем он сказал ИИ: «Измени `count + 1` на `count + 2`».

С первого раза исправилось правильно.

**Вот почему нужно понимать JavaScript — не чтобы писать код вручную, а чтобы, когда ИИ исправил неправильно, вы с одного взгляда видели, где проблема, и одной фразой попадали точно в цель.**
:::

### 1.3 Краткий обзор: реальный код от ИИ

Прежде чем погружаться в детали, давайте сначала посмотрим на реальный код, сгенерированный ИИ. Не переживайте, если что-то непонятно, просто получите общее представление — дальше мы разберём каждую часть по отдельности.

**Сценарий**: сделать функцию «нажатие на кнопку меняет цвет фона»

```javascript
// 定义一组颜色
const colors = ['#ff6b6b', '#4ecdc4', '#45b7d1', '#96ceb4']
let currentIndex = 0

// 找到页面上的按钮
const button = document.querySelector('#changeBtn')

// 给按钮添加点击事件
button.addEventListener('click', () => {
  currentIndex = (currentIndex + 1) % colors.length
  document.body.style.backgroundColor = colors[currentIndex]
})
```

**Что делает этот код?**

| Код | Назначение | Соответствующая глава |
|------|------|----------|
| `const colors = [...]` | Определяет набор данных о цветах | Глава 2: массивы |
| `let currentIndex = 0` | Запоминает, какой цвет отображается сейчас | Глава 2: переменные |
| `document.querySelector(...)` | Находит кнопку на странице | Глава 4: поиск в DOM |
| `button.addEventListener(...)` | Добавляет кнопке обработчик клика | Глава 4: прослушивание событий |
| `() => {...}` | Определяет код, выполняемый после клика | Глава 3: стрелочные функции |

::: info 💡 Ключевая идея
Вам не нужно прямо сейчас понимать каждую строку кода. Достаточно запомнить: **код на JavaScript — это серия инструкций, которые говорят браузеру «когда пользователь делает что-то, должно произойти то-то».**
:::

## 2. Данные: переменные и типы данных

::: tip 🤔 Ключевой вопрос
**Как программа «запоминает» вещи?** Введённое пользователем содержимое, данные, полученные с сервера, промежуточные результаты вычислений — где всё это хранится?
:::

### 2.1 Переменные: дать данным имя

**Переменная — как коробка с этикеткой**: вы можете положить в неё данные и потом достать их по этикетке.

```javascript
const name = "张三"   // 名字不会变，用 const
let age = 25          // 年龄可能会变，用 let
```

**Зачем различать const и let?**

Представьте: номер вашего паспорта (const) не меняется всю жизнь, но ваш возраст (let) меняется каждый год. JavaScript позволяет с помощью разных ключевых слов выразить это намерение «изменяемое или неизменяемое».

| Ключевое слово | Можно ли изменять | Сценарий использования | Пример |
|--------|---------|----------|------|
| `const` | ❌ Нельзя | Данные, значение которых не меняется | Номер паспорта, настройки, список цветов |
| `let` | ✅ Можно | Данные, значение которых меняется | Счётчик, текущий выбранный вариант, ввод пользователя |

::: details 🔍 Рассмотрим конкретный пример
```javascript
// 用 const：这些值不会变
const PI = 3.14159
const MAX_USERS = 100
const APP_NAME = "TodoList"

// 用 let：这些值会变化
let count = 0
count = 1  // ✅ 可以修改

count = count + 1  // ✅ 可以基于原值计算

// 如果用 const 会怎样？
const fixedCount = 0
fixedCount = 1  // ❌ 报错！const 不能重新赋值
```
:::

### 2.2 Типы данных: несколько видов «вещей» в JavaScript

JavaScript делит данные на несколько типов, самых распространённых три:

| Тип | Описание | Пример | Реальный сценарий |
|------|------|------|----------|
| `string` (строка) | Текстовое содержимое | `"hello"`, `'你好'` | Имя пользователя, описание товара, подсказка |
| `number` (число) | Числовое значение | `42`, `3.14` | Цена, количество, оценка |
| `boolean` (логическое значение) | Да/нет | `true`, `false` | Вошёл ли в систему, завершено ли, видимо ли |

**Также нужно знать два особых значения:**

- `undefined` → переменная объявлена, но значение ещё не присвоено
- `null` → намеренно установлено пустым (означает «здесь нет значения»)

::: details 🔍 Шаблонные строки: удобнее склеивать текст
В коде от ИИ вы часто будете видеть строки, обёрнутые в обратные кавычки (`` ` ``), внутри которых ещё есть `${...}`:

```javascript
const name = "张三"
const age = 25

// 传统写法（麻烦）
const message = "我叫" + name + "，今年" + age + "岁"

// 模板字符串（简洁）
const message = `我叫${name}，今年${age}岁`
// 结果："我叫张三，今年25岁"
```

**Ключевой момент распознавания**: увидев обратные кавычки и `${}`, знайте, что в текст вставляется переменная.
:::

### 2.3 Объекты и массивы: организуем данные

**Объект = набор именованных свойств** (как анкета с личной информацией)

```javascript
const user = {
  name: "张三",
  age: 25,
  isVIP: true
}

// 使用点号访问属性
console.log(user.name)    // "张三"
console.log(user.age)     // 25
```

**Массив = набор упорядоченных данных** (как список)

```javascript
const colors = ['红色', '绿色', '蓝色']

// 用索引访问（从 0 开始）
console.log(colors[0])  // "红色"
console.log(colors[1])  // "绿色"
```

**Вложенные структуры: массив внутри объекта, объект внутри массива**

Это самая распространённая структура данных в коде от ИИ:

```javascript
const todos = [
  { id: 1, text: "学习 JavaScript", done: false },
  { id: 2, text: "做项目", done: true },
  { id: 3, text: "写文档", done: false }
]

// 访问：先取数组的第 0 项，再取它的 text 属性
console.log(todos[0].text)  // "学习 JavaScript"
```

::: info 💡 Приёмы распознавания
- Увидев `{}` → это объект, внутри набор `имя: значение`
- Увидев `[]` → это массив, внутри набор значений в определённом порядке
- Увидев `data[0].name` → сначала берём элемент массива с индексом 0, затем его свойство name
:::

### 2.4 Значение и ссылка: распространённая ловушка

Это одна из самых частых проблем у новичков!

**Присваивание примитивных типов (string, number, boolean) = копирование совершенно новых данных:**

```javascript
let a = 10
let b = a      // b 得到 a 的副本
b = 20
console.log(a) // 10（a 不受影响）
```

**Присваивание объектов и массивов = копируется «адрес» (указывает на одну и ту же вещь):**

```javascript
let user1 = { name: "张三" }
let user2 = user1      // user2 指向同一个对象
user2.name = "李四"     // 修改 user2 会影响 user1
console.log(user1.name) // "李四"（user1 也变了！）
```

**Зачем создавать копию?**

В React/Vue прямое изменение данных приводит к тому, что интерфейс не обновляется. Поэтому в коде от ИИ часто встречаются `[...array]` или `{...obj}` — они создают копию, чтобы избежать взаимного влияния.

```javascript
// 用展开运算符创建副本
const arr1 = [1, 2, 3]
const arr2 = [...arr1]     // 创建新数组
arr2.push(4)
console.log(arr1)          // [1, 2, 3]（不受影响）
console.log(arr2)          // [1, 2, 3, 4]
```

### 2.5 Деструктуризация и расширение: современные сокращённые записи JavaScript

Эти два синтаксиса встречаются в коде от ИИ повсюду, не зная их, вы не поймёте код.

**Деструктуризирующее присваивание: быстро извлекаем данные из объекта или массива**

```javascript
const user = { name: "张三", age: 25, city: "北京" }

// 传统写法（麻烦）
const name = user.name
const age = user.age

// 解构写法（简洁）
const { name, age } = user
// 效果一样，但一行搞定
```

**Оператор расширения: копируем и дополняем данные**

```javascript
// 复制数组并添加新元素
const arr1 = [1, 2, 3]
const arr2 = [...arr1, 4, 5]  // [1, 2, 3, 4, 5]

// 复制对象并添加新属性
const user1 = { name: "张三", age: 25 }
const user2 = { ...user1, city: "北京" }
// { name: "张三", age: 25, city: "北京" }
```

::: info 💡 Приёмы распознавания
- Увидев `const { name, age } = person` → извлекаем name и age из объекта person
- Увидев `...array` или `...obj` → раскрываем массив или объект
- Вам не нужно уметь писать это вручную, но нужно уметь читать
:::

## 3. Логика: функции и управление потоком

::: tip 🤔 Ключевой вопрос
**Как код «принимает решения» и «повторяет действия»?** Программе нужно выполнять разные операции в зависимости от условий, а также повторять некоторые задачи — как выразить эту логику?
:::

### 3.1 Условные проверки: если... то... иначе...

**if/else: самая базовая условная проверка**

```javascript
const age = 18

if (age >= 18) {
  console.log("成年人")
} else {
  console.log("未成年")
}
```

**Тернарный оператор: сокращённая запись if/else**

```javascript
// 完整写法（4 行）
let message
if (age >= 18) {
  message = "成年人"
} else {
  message = "未成年"
}

// 三元运算符（1 行）
const message = age >= 18 ? "成年人" : "未成年"
// 格式：条件 ? 条件为真时的值 : 条件为假时的值
```

**Сокращённая запись с &&: часто встречается в коде React**

```javascript
// 只有 isLoggedIn 为 true 时才显示用户面板
isLoggedIn && <UserPanel />

// 等价于
if (isLoggedIn) {
  return <UserPanel />
}
```

::: info 💡 Приёмы распознавания
- Увидев `? :` → это тернарный оператор, сокращённая запись if/else
- Увидев `&&` → выполнение того, что справа, только если слева true
:::

### 3.2 Функции: упаковываем операции

**Функция = рецепт блюда**

- Определение функции = записать рецепт
- Вызов функции = приготовить по рецепту
- Параметры = ингредиенты
- Возвращаемое значение = готовое блюдо

```javascript
// 定义函数（写下配方）
function greet(name) {
  return "Hello " + name
}

// 调用函数（按配方做菜）
console.log(greet("张三"))  // "Hello 张三"
console.log(greet("李四"))  // "Hello 李四"
```

**Три способа записи, распознаваемые с первого взгляда:**

```javascript
// 1. function 声明（传统写法）
function greet(name) {
  return "Hello " + name
}

// 2. 箭头函数（AI 代码里用得最多）
const greet = (name) => {
  return "Hello " + name
}

// 3. 箭头函数简写（只有一行时）
const greet = (name) => "Hello " + name
```

### 3.3 Методы массивов: мощный инструмент для работы со списками

В React/Vue почти при каждом рендеринге списка используются эти методы.

```javascript
const todos = [
  { id: 1, text: "学习", done: false },
  { id: 2, text: "工作", done: true }
]

// .map()：把数组的每一项变成另一个东西
const texts = todos.map(todo => todo.text)
// ["学习", "工作"]

// .filter()：筛选出符合条件的项
const unfinished = todos.filter(todo => !todo.done)
// [{ id: 1, text: "学习", done: false }]

// .find()：找到第一个符合条件的项
const found = todos.find(todo => todo.id === 1)
// { id: 1, text: "学习", done: false }
```

::: info 💡 Приёмы распознавания
- Увидев `.map()` → преобразование массива, возвращается новый массив
- Увидев `.filter()` → фильтрация массива
- Увидев `items.map(item => <li>{item.name}</li>)` → превращение каждого элемента данных в тег списка
:::

### 3.4 Область видимости: «зона видимости» переменных

**Метафора «комнаты»:**

- Переменные внутри функции — как вещи в комнате, снаружи их не видно
- Но люди в комнате могут видеть коридор (внешнюю область видимости)

```javascript
const global = "全局变量"  // 走廊里的东西

function room() {
  const local = "房间里的东西"  // 房间里的东西
  console.log(global)  // ✅ 能看到走廊
}

console.log(local)  // ❌ 报错！外面看不到房间里的东西
```

**Ключевая интуиция:** где написан код, то и определяет, какие переменные он видит.

### 3.5 Замыкание: функция «запомнила» окружение, в котором родилась

**Не воспринимайте это как отдельную концепцию, поймите на конкретном сценарии:**

```javascript
function setupCounter() {
  let count = 0  // 这个变量在函数内部

  return {
    add: () => { count++; return count },
    getCount: () => count
  }
}

const counter = setupCounter()
console.log(counter.add())      // 1
console.log(counter.add())      // 2
console.log(counter.getCount()) // 2
```

**Ключевая интуиция:** при создании функция «запоминает» окружающие её переменные, даже если внешняя функция уже завершила выполнение.

### 3.6 this: кто вызвал функцию

**Не будем говорить о сложных правилах привязки, рассмотрим только самые частые сценарии:**

**Сценарий 1: в методе объекта this указывает на этот объект**

```javascript
const user = {
  name: "张三",
  sayHi() {
    console.log("你好，我是" + this.name)  // this 指向 user
  }
}
user.sayHi()  // "你好，我是张三"
```

**Сценарий 2: в обработчике события this указывает на элемент, вызвавший событие**

```javascript
button.addEventListener('click', function() {
  console.log(this)  // this 指向 button 元素
})

// 但箭头函数不会改变 this
button.addEventListener('click', () => {
  console.log(this)  // this 指向外层的 this
})
```

::: info 💡 Что делать при возникновении проблемы?
Если в коде от ИИ появляется баг, связанный с this (например, `Cannot read property of undefined`), скажите ИИ: «this в этом методе указывает не туда, замени на стрелочную функцию или используй bind»
:::

### 4.3 События: когда пользователь совершил какое-то действие...

**addEventListener: добавляем элементу обработчик события**

```javascript
button.addEventListener('click', () => {
  console.log("按钮被点击了")
})
```

**Распространённые события:**

| Событие | Когда срабатывает | Реальный сценарий |
|------|---------|----------|
| `click` | Клик | Нажатие кнопки, переход по ссылке |
| `input` | Изменение содержимого поля ввода | Поиск в реальном времени, валидация формы |
| `submit` | Отправка формы | Вход, регистрация, отправка данных |
| `scroll` | Прокрутка страницы | Ленивая загрузка, возврат наверх |

**Объект события: получаем больше информации**

```javascript
input.addEventListener('input', (e) => {
  console.log(e.target.value)  // 获取输入框的值
  e.preventDefault()            // 阻止默认行为（比如表单提交后刷新页面）
})
```

::: info 💡 Практическое применение
Когда вы хотите добавить кнопке функцию, по сути вы говорите ИИ: «Добавь этой кнопке обработчик клика, после клика выполни такую-то операцию»
:::

### 4.4 Асинхронность: почему некоторые операции выполняются не мгновенно

**Метафора ресторана:**

Сделав заказ, не нужно стоять у дверей кухни и ждать, можно заняться другими делами, а когда блюдо будет готово, официант его принесёт.

**Самый частый сценарий: получение данных с сервера**

```javascript
// 同步写法（会卡住页面，不要用）
const data = fetch('/api/data')  // ❌ 这样写会卡住

// 异步写法（正确）
async function loadData() {
  try {
    const response = await fetch('/api/data')
    const data = await response.json()
    console.log(data)
  } catch (error) {
    console.error('出错了:', error)
  }
}
```

**Синтаксис async/await:**

- `async` → помечает, что в этой функции есть асинхронные операции
- `await` → ждёт завершения этой операции (но не блокирует страницу)
- `try/catch` → обрабатывает возможные ошибки

- Увидев `async/await` → ожидание длительной операции
- Увидев `fetch()` → получение данных с сервера
- Увидев `try/catch` → обработка возможных ошибок

### 4.5 Цикл событий: как же на самом деле работает JavaScript

**Не будем использовать термины «микрозадача/макрозадача», поймём через простую модель:**

**JS — это «рабочее место для одного человека»**, который одновременно делает только одно дело, но у него есть «доска со стикерами дел» (очередь задач).

Встретив операцию, которую нужно ждать (сетевой запрос, таймер), JS не стоит и не ждёт, а наклеивает на доску стикер «что делать, когда будет готово», и продолжает выполнять дальше. Закончив текущее дело, он смотрит на доску со стикерами.

```javascript
console.log("1")

setTimeout(() => console.log("2"), 0)  // 即使是 0 秒，也会推迟

console.log("3")

// 输出：1, 3, 2（不是 1, 2, 3！）
```

**Почему?**
1. Выполняется `console.log("1")` → вывод 1
2. Встречается `setTimeout` → колбэк наклеивается на доску, продолжаем дальше
3. Выполняется `console.log("3")` → вывод 3
4. Текущий код выполнен, смотрим на доску со стикерами
5. Выполняется колбэк `setTimeout` → вывод 2

### 4.6 Модули: import и export

Первая строка сгенерированного ИИ кода React/Vue почти всегда — это `import`.

**import = подключаем функционал из другого файла**

```javascript
// 从工具文件引入函数
import { formatDate } from './utils'

// 从第三方包引入
import React from 'react'
import { useState } from 'react'
```

**export = открываем функционал, чтобы другие могли его использовать**

```javascript
// utils.js
export function formatDate(date) {
  // ...
}

// 或者默认导出
export default function formatDate(date) {
  // ...
}
```

**npm-пакет = готовый инструмент, написанный другими, после установки можно использовать**

```javascript
// 安装包：npm install lodash
// 使用包
import _ from 'lodash'
```

::: info 💡 Приёмы распознавания
- Увидев `import` → подключение функционала из другого файла
- Увидев `export` → открытие функционала для других
- Увидев `from 'react'` → подключение из пакета React
- Увидев `from './utils'` → подключение из локального файла
:::

### 5.1 Как читать код после получения его от ИИ

**Метод четырёх шагов:**

| Шаг | На что смотреть | Пример |
|------|--------|------|
| **Шаг 1: смотрим общую структуру** | Сколько функций? Что каждая делает? | `loadData()` загружает данные, `renderList()` рендерит список |
| **Шаг 2: ищем точку входа** | Откуда программа начинает выполнение? | `addEventListener('click', ...)` начинается при клике |
| **Шаг 3: отслеживаем поток данных** | Откуда приходят данные? Куда идут? | Из API → разбор → рендеринг на странице |
| **Шаг 4: смотрим детали логики** | Как конкретная функция обрабатывает? | Циклы, проверки, вычисления |

**Сделаем полную «демонстрацию чтения» на примере кода из главы 1:**

```javascript
// 第一步：整体结构
// - 一个颜色数组
// - 一个变量记录当前索引
// - 一个按钮的点击事件

// 第二步：入口点
// button.addEventListener('click', ...) → 点击按钮时执行

// 第三步：数据流
// colors（颜色数组）→ currentIndex（当前索引）→ backgroundColor（背景色）

// 第四步：细节逻辑
// currentIndex = (currentIndex + 1) % colors.length
// 这个公式的意思：每次 +1，但不超过数组长度（循环）
```

### 5.2 Краткий справочник по распространённым ошибкам

| Ошибка | Объяснение простым языком | Как сказать ИИ |
|------|-----------|-------------|
| `TypeError: Cannot read properties of undefined` | Вы пытаетесь взять значение из несуществующей вещи | «В строке X ошибка, такая-то переменная undefined, проверь логику её присваивания» |
| `ReferenceError: xxx is not defined` | Использовано необъявленное имя переменной | «Переменная xxx не определена, может, опечатка или забыли импортировать» |
| `TypeError: xxx is not a function` | То, что не является функцией, вызвано как функция | «xxx не функция, проверь её тип и происхождение» |
| `SyntaxError: Unexpected token` | Синтаксическая ошибка (несовпадение скобок, пропущена запятая и т. д.) | «В строке X синтаксическая ошибка, проверь скобки и знаки препинания» |
| `CORS error` | Браузер заблокировал межсайтовый запрос | «Возникла ошибка CORS, нужно настроить совместное использование межсайтовых ресурсов» |
| `404 Not Found` | Запрашиваемый ресурс не существует | «API возвращает 404, проверь правильность адреса интерфейса» |

### 5.3 Как точно описать проблему

Разница между новичком и опытным разработчиком часто проявляется именно в **точности описания проблемы**.

| ❌ Плохое описание | ✅ Хорошее описание |
|-----------|-----------|
| «В коде баг» | «При нажатии на кнопку удаления удаляется не текущий элемент, а последний» |
| «Стиль неправильный» | «Заголовок должен быть по центру, сейчас он по левому краю» |
| «Данные не отображаются» | «Запрос fetch вернул данные (видно в консоли), но страница не перерендерилась» |
| «Добавь функцию» | «Добавь на страницу списка пользователей поле поиска, при вводе фильтруй список в реальном времени по нечёткому совпадению поля name» |
| «Клик не реагирует» | «При нажатии на кнопку в консоли ошибка 'Cannot read property of undefined', ошибка в строке X» |

**Практическое упражнение:**

```javascript
// 有 bug 的代码
function deleteTodo(index) {
  todos.splice(index, 1)  // 总是删除最后一项
}

// 错误现象：无论点哪个删除按钮，删的都是最后一项
```

**❌ Плохое описание:** «В функции удаления баг»

**✅ Хорошее описание:** «При нажатии на кнопку удаления удаляется не текущий элемент, а последний. В коде используется splice(index, 1), но index, возможно, неправильный. Нужно изменить так, чтобы удалять по уникальному id каждого элемента.»

### 5.4 Код, который вы теперь должны уметь распознавать

- Увидев `const/let` → знаете, можно ли переменной присвоить значение заново
- Увидев `{}` → объект / увидев `[]` → массив
- Увидев `{...obj}` или `[...arr]` → создаётся копия
- Увидев `function` или `=>` → определена повторно выполняемая операция
- Увидев `if/else` или `? :` → код принимает решение
- Увидев `.map()` / `.filter()` → преобразование или фильтрация массива
- Увидев `document.querySelector` → поиск элемента страницы
- Увидев `addEventListener` → прослушивание действий пользователя
- Увидев `async/await` → ожидание длительной операции
- Увидев `import/export` → подключение или экспорт модуля
- Встретив ошибку → можете понять её суть и точно описать ИИ

**Если вы внимательно прочитали разделы «Подробнее» в каждой главе, то освоили ещё и эти ключевые концепции:**

- **Значение vs ссылка**: примитивные типы копируют значение, объекты/массивы копируют адрес
- **Область видимости и замыкание**: функция может «запомнить» окружающие её при рождении переменные

Эти концепции помогут вам быстрее локализовать проблему.
