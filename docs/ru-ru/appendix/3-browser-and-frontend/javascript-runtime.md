# Подробное руководство по среде выполнения JavaScript

::: tip Предисловие
Вы уже освоили базовый синтаксис JavaScript, но задумывались ли вы:
- Где на самом деле выполняется код?
- Почему один и тот же код в браузере и в Node.js ведёт себя по-разному?
- Почему иногда код «зависает», а иногда выполняется «параллельно»?

Эта статья поможет вам глубже понять среду выполнения JavaScript, включая цикл событий, стек вызовов, управление памятью и многое другое. Прочитав её, вы поймёте, почему код выполняется в определённом порядке, сможете быстро локализовать баги, связанные с асинхронностью, оптимизировать производительность кода и избегать утечек памяти.
:::

## 1. Обзор среды выполнения

::: tip 🤔 Ключевой вопрос
**Что такое «среда выполнения»?** JavaScript — это всего лишь язык, почему один и тот же код в разных средах ведёт себя по-разному?
:::

### 1.1 Что такое среда выполнения

**Среда выполнения = движок JavaScript + API, предоставляемые средой**

Если сравнить JavaScript с «языком программирования», то среда выполнения — это «операционная система»: она определяет, что ваш код может делать, а что нет.

```
┌─────────────────────────────────────┐
│         JavaScript 代码             │
├─────────────────────────────────────┤
│      JavaScript 引擎 (V8)           │  ← 负责解析和执行代码
├─────────────────────────────────────┤
│      运行时环境 (浏览器/Node.js)     │  ← 提供额外能力
└─────────────────────────────────────┘
```

**Метафора: JavaScript — это «литературный язык», среда выполнения — это «город»**

- Синтаксис JavaScript (литературный язык) везде одинаков
- Но разные города предоставляют разную инфраструктуру:
  - Браузер = есть DOM, window, fetch (как в городе есть торговые центры, библиотеки)
  - Node.js = есть fs, http, path (как в городе есть заводы, автомагистрали)

### 1.2 Две основные среды выполнения

| Характеристика | Браузер | Node.js |
|------|--------|---------|
| **Основное назначение** | Взаимодействие со страницей, пользовательский интерфейс | Серверные приложения, инструменты командной строки |
| **Глобальный объект** | `window` | `global` |
| **DOM API** | ✅ Поддерживается | ❌ Не поддерживается |
| **Файловая система** | ❌ Ограничена | ✅ Полная поддержка |
| **Модульная система** | ES Modules | CommonJS + ES Modules |
| **Таймеры** | `setTimeout`, `setInterval` | `setTimeout`, `setInterval` |
| **Сетевые запросы** | `fetch`, `XMLHttpRequest` | Модули `http`, `https` |

## 2. Среда выполнения браузера

::: tip 🤔 Ключевой вопрос
**Какие возможности предоставляет браузер, чтобы JavaScript мог управлять страницей?**
:::

### 2.1 Состав среды выполнения браузера

```
┌─────────────────────────────────────────────┐
│            JavaScript 引擎                  │
│            (V8 / SpiderMonkey)              │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│              Web APIs                        │
│  ┌─────────┐ ┌──────────┐ ┌──────────┐     │
│  │   DOM   │ │   BOM    │ │ Network  │     │
│  │  操作网页 │ │ 操作浏览器 │ │ 网络请求  │     │
│  └─────────┘ └──────────┘ └──────────┘     │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│           事件循环 (Event Loop)              │
│     负责协调代码执行、事件处理、任务调度        │
└─────────────────────────────────────────────┘
```

### 2.2 Три категории Web API

**1. DOM API — управление содержимым страницы**

```javascript
// 查找元素
const title = document.querySelector('h1')

// 修改内容
title.textContent = '新标题'

// 添加样式
title.style.color = 'red'
```

**2. BOM API — управление браузером**

```javascript
// 页面跳转
window.location.href = 'https://example.com'

// 浏览器存储
localStorage.setItem('key', 'value')

// 浏览器历史
history.back()
```

**3. Network API — сетевые запросы**

```javascript
// 发送 HTTP 请求
fetch('/api/data')
  .then(response => response.json())
  .then(data => console.log(data))
```

### 2.3 Механизм событий, характерный для браузера

Одна из самых мощных возможностей среды выполнения браузера — это «событийно-ориентированность»: коду не нужно работать постоянно, он выполняется только при действии пользователя.

```javascript
button.addEventListener('click', () => {
  console.log('按钮被点击了')
})
```

**Распространённые типы событий:**

| Тип события | Когда срабатывает | Реальный сценарий |
|---------|---------|---------|
| `click` | Клик мышью | Взаимодействие с кнопкой |
| `input` | Изменение содержимого поля ввода | Поиск в реальном времени |
| `scroll` | Прокрутка страницы | Ленивая загрузка |
| `load` | Завершение загрузки ресурса | Инициализация данных |
| `error` | Возникновение ошибки | Обработка ошибок |

## 3. Среда выполнения Node.js

::: tip 🤔 Ключевой вопрос
**За счёт чего JavaScript может выполняться на сервере?**
:::

### 3.1 Состав Node.js

```
┌─────────────────────────────────────────────┐
│            JavaScript 引擎                  │
│                 (V8)                        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│           Node.js 内置模块                   │
│  ┌─────────┐ ┌──────────┐ ┌──────────┐     │
│  │   fs    │ │   http   │ │   path   │     │
│  │ 文件操作 │ │ 网络服务器 │ │ 路径处理  │     │
│  └─────────┘ └──────────┘ └──────────┘     │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│          libuv 事件循环库                    │
│      跨平台的异步 I/O 支持                   │
└─────────────────────────────────────────────┘
```

### 3.2 Возможности, характерные для Node.js

**1. Операции с файловой системой**

```javascript
const fs = require('fs')

// 读取文件
fs.readFile('./data.txt', 'utf8', (err, data) => {
  if (err) throw err
  console.log(data)
})

// 写入文件
fs.writeFile('./output.txt', 'Hello', (err) => {
  if (err) throw err
  console.log('写入成功')
})
```

**2. HTTP-сервер**

```javascript
const http = require('http')

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html' })
  res.end('<h1>Hello World</h1>')
})

server.listen(3000)
```

**3. Модульная система**

```javascript
// CommonJS (Node.js 默认)
const fs = require('fs')
module.exports = { myFunction }

// ES Modules (现代方式)
import fs from 'fs'
export { myFunction }
```

### 3.3 Сравнение браузера и Node.js

| Характеристика | Браузер | Node.js |
|------|--------|---------|
| **Входной файл** | HTML-файл | JavaScript-файл |
| **Глобальный объект** | `window`, `document` | `global`, `process` |
| **Загрузка модулей** | Тег `<script>` | `require()` / `import` |
| **Безопасность** | Среда-песочница, ограниченная | Можно обращаться к системным ресурсам |
| **Назначение** | Пользовательский интерфейс | Бэкенд-сервисы, инструменты |

## 4. Углубление в цикл событий

::: tip 🤔 Ключевой вопрос
**JavaScript однопоточен, почему же он может быть «неблокирующим»?**
:::

### 4.1 Что такое цикл событий

**Цикл событий = «центр планирования задач» JavaScript**

JavaScript однопоточен, он может делать только одно дело за раз. Но цикл событий позволяет ему выглядеть так, будто он делает много дел «одновременно».

**Основной механизм:**

1. **Выполнение синхронного кода** (стек вызовов)
2. **Обработка асинхронных задач** (очередь задач)
3. **Ожидание новых задач** (повторение по кругу)

```
调用栈                    任务队列
┌─────────┐              ┌──────────┐
│ 任务 1  │              │ 宏任务 1  │
│ 任务 2  │ ←────────────  │ 宏任务 2  │
│ 任务 3  │   执行完一个   │ 宏任务 3  │
└─────────┘   就取下一个  └──────────┘
      ↓                        ↑
      └────────────────────────┘
         事件循环不断检查
```

### 4.2 Макрозадачи vs микрозадачи

Это самое легко путаемое понятие на собеседованиях и в реальной разработке!

**Макрозадачи (Macrotask):**
- `setTimeout`, `setInterval`
- Операции ввода-вывода
- Рендеринг UI

**Микрозадачи (Microtask):**
- `Promise.then`
- `MutationObserver`
- `queueMicrotask`

**Порядок выполнения: синхронный код → микрозадачи → макрозадачи**

👇 **Попробуйте сами**: понаблюдайте за порядком выполнения макро- и микрозадач

<TaskQueueDemo />

### 4.3 Классическая задача с собеседования

```javascript
console.log('1')

setTimeout(() => console.log('2'), 0)

Promise.resolve().then(() => console.log('3'))

console.log('4')

// 输出: 1, 4, 3, 2
```

**Почему именно такой порядок?**

1. Выполняется синхронный код: `console.log('1')`, `console.log('4')` → вывод 1, 4
2. Проверяется очередь микрозадач: `Promise.then` → вывод 3
3. Проверяется очередь макрозадач: `setTimeout` → вывод 2

::: info 💡 Практический приём
- Если хотите, чтобы код выполнился как можно скорее, используйте микрозадачи (`Promise.then`)
- Если хотите отложить выполнение, используйте макрозадачи (`setTimeout`)
- Никогда не смешивайте слишком много асинхронных операций, иначе попадёте в «ад колбэков»
:::

## 5. Стек вызовов и память

::: tip 🤔 Ключевой вопрос
**Как выполняется код? Где хранятся переменные? Когда они освобождаются?**
:::

### 5.1 Стек вызовов: «следы» выполнения функций

**Стек вызовов = «блокнот», записывающий вызовы функций**

При каждом вызове функции в стек добавляется новая запись; когда функция завершает выполнение, запись удаляется.

```javascript
function a() {
  b()
}

function b() {
  c()
}

function c() {
  console.log('执行完毕')
}

a()
```

**Изменения стека вызовов:**

```
步骤 1: 调用 a()
┌─────────┐
│    a    │
└─────────┘

步骤 2: a() 调用 b()
┌─────────┐
│    b    │
│    a    │
└─────────┘

步骤 3: b() 调用 c()
┌─────────┐
│    c    │
│    b    │
│    a    │
└─────────┘

步骤 4: c() 执行完,依次弹出
┌─────────┐
│    b    │
│    a    │
└─────────┘
```

### 5.2 Управление памятью: куда делся мусор

В JavaScript есть механизм «автоматической сборки мусора» — вам не нужно вручную освобождать память, движок сделает это за вас.

**Принцип сборки мусора: алгоритм «пометка-очистка»**

1. **Фаза пометки**: начиная от «корня», находятся все доступные переменные
2. **Фаза очистки**: непомеченные переменные — это «мусор», они освобождаются

```javascript
// 垃圾回收示例
let obj1 = { name: '对象1' }
let obj2 = { name: '对象2' }

// obj1 被重新赋值,原来的对象失去了引用
obj1 = null  // 原来的 { name: '对象1' } 会被回收

// obj2 还在使用中,不会被回收
console.log(obj2.name)
```

### 5.3 Утечка памяти: последствия забытой очистки

**Утечка памяти = память, которую нужно было освободить, не освобождена и накапливается всё больше**

Распространённые причины:

**1. Слишком много глобальных переменных**

```javascript
// ❌ 错误:全局变量不会被回收
globalCache = []

function addItem(item) {
  globalCache.push(item)
}
```

**2. Обработчики событий не удалены**

```javascript
// ❌ 错误:监听器没移除
button.addEventListener('click', handleClick)

// ✅ 正确:不需要时移除监听
button.removeEventListener('click', handleClick)
```

**3. Замыкание ссылается на большой объект**

```javascript
// ❌ 错误:闭包一直引用大对象,不会被回收
function createHandler() {
  const bigData = new Array(1000000).fill('data')
  return function() {
    console.log('处理中')
  }
}

const handler = createHandler()  // bigData 一直存在于内存中
```

## 6. Практические приёмы

::: tip 🤔 Ключевой вопрос
**Как писать высокопроизводительный код на JavaScript? Как отлаживать при возникновении проблем?**
:::

### 6.1 Приёмы оптимизации производительности

**1. Уменьшение перекомпоновки и перерисовки**

```javascript
// ❌ 错误:每次循环都触发重排
for (let i = 0; i < 1000; i++) {
  element.style.top = i + 'px'
}

// ✅ 正确:批量修改
element.style.transform = `translateY(${position}px)`
```

**2. Использование делегирования событий**

```javascript
// ❌ 错误:给每个按钮都添加监听
buttons.forEach(btn => {
  btn.addEventListener('click', handleClick)
})

// ✅ 正确:只给父元素添加一个监听
container.addEventListener('click', (e) => {
  if (e.target.matches('.button')) {
    handleClick(e)
  }
})
```

**3. Подавление дребезга (debounce) и тротлинг (throttle)**

```javascript
// 防抖:用户停止输入后再执行
function debounce(fn, delay) {
  let timer
  return function(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}

// 节流:限制执行频率
function throttle(fn, delay) {
  let lastTime = 0
  return function(...args) {
    const now = Date.now()
    if (now - lastTime >= delay) {
      fn.apply(this, args)
      lastTime = now
    }
  }
}
```

### 6.2 Приёмы отладки

**1. Просмотр стека вызовов через DevTools**

```javascript
function a() {
  b()
}

function b() {
  c()
}

function c() {
  debugger  // 在这里暂停,查看调用栈
}

a()
```

**2. Отслеживание пути выполнения через `console.trace()`**

```javascript
function trackExecution() {
  console.trace('执行路径')
  // 会输出完整的调用栈
}
```

**3. Анализ производительности через Performance**

```javascript
performance.mark('start')

// 执行一些代码
for (let i = 0; i < 10000; i++) {
  // ...
}

performance.mark('end')
performance.measure('循环性能', 'start', 'end')

const measure = performance.getEntriesByName('循环性能')[0]
console.log(`执行时间: ${measure.duration}ms`)
```

### 6.3 Краткий справочник по распространённым проблемам

| Проблема | Возможная причина | Решение |
|------|---------|---------|
| **Высокое использование памяти** | Утечка памяти, слишком много кэша | Проверить глобальные переменные, удалить обработчики |
| **Подвисание страницы** | Длинная задача блокирует главный поток | Разбить задачу, использовать Web Workers |
| **Событие не срабатывает** | Обработчик не привязан, элемент не существует | Проверить момент загрузки DOM |
| **Нарушен порядок асинхронности** | Смешаны макро- и микрозадачи | Единообразно использовать Promise или async/await |
| **Таймер неточен** | Главный поток заблокирован | Использовать Web Workers или requestAnimationFrame |

## Итоги

Теперь вы должны понимать:

- **Среда выполнения = движок + API среды**, разные среды выполнения предоставляют разные возможности
- **Цикл событий** отвечает за координацию порядка выполнения синхронного кода, микро- и макрозадач
- **Стек вызовов** записывает процесс выполнения функций, **переполнение стека** возникает из-за слишком глубокой рекурсии
- **Сборка мусора** автоматически очищает неиспользуемые переменные, но нужно следить за **утечками памяти**
- Ключ к **оптимизации производительности** — уменьшение перекомпоновки и перерисовки, разумное использование асинхронности

::: info 💡 Так говорите ИИ при возникновении проблемы
- «Эта функция выполняется слишком медленно, помоги разобраться, как оптимизировать производительность»
- «Использование памяти постоянно растёт, возможно, это утечка памяти, помоги проверить»
- «Порядок асинхронных операций неправильный, должно быть сначала A, потом B, а сейчас A и B начинаются почти одновременно»
- «Обработчик события не сработал, проверь, загружен ли уже элемент в DOM»
:::
