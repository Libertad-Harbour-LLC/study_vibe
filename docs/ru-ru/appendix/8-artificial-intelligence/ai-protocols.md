# Протоколы AI Agent (MCP и A2A)

::: tip Ключевой вопрос
**Как AI Agent «разговаривает» с внешним миром?** Так же как интернету нужен протокол HTTP, AI Agent тоже нужны стандартизированные протоколы связи. В этой главе мы рассмотрим два самых популярных протокола Agent: MCP и A2A. Они решают, соответственно, проблемы связи между AI и инструментами, а также между Agent и Agent.
:::

---

## 0. Что такое протокол?

В сфере компьютеров **протокол (Protocol)** — это набор стандартизированных правил и договорённостей, позволяющий разным системам и программам «понимать» друг друга и «общаться».

### 0.1 Зачем нужны протоколы?

Представьте себе ситуацию: вы отправляете другу посылку и должны указать адрес. Если бы каждый писал адрес в своём формате, курьер не смог бы её доставить. Протокол как раз задаёт стандарт «как писать адрес» — область, город, район, улица, номер дома. Если писать по этому формату, любой поймёт.

С компьютерами то же самое. Чтобы две программы обменивались данными, они должны договориться:
- Каков формат данных? (JSON? двоичный?)
- Как устанавливается соединение? (процедура рукопожатия)
- Что делать при ошибке? (обработка ошибок)

### 0.2 Распространённые протоколы в компьютерах

| Протокол | Назначение | Вы пользуетесь этим каждый день |
|------|------|-------------|
| **HTTP** | Протокол передачи веб-страниц | Браузер открывает веб-страницу |
| **HTTPS** | Зашифрованный HTTP | Интернет-банк, страницы оплаты |
| **TCP/IP** | Базовый протокол интернета | Вся сетевая связь |
| **DNS** | Протокол разрешения доменных имён | Превращает `google.com` в IP-адрес |
| **SMTP** | Протокол отправки почты | Отправка писем |
| **WebSocket** | Двусторонняя связь в реальном времени | Мессенджеры, онлайн-игры |
| **SSH** | Безопасный удалённый вход | Подключение к серверу |
| **FTP** | Протокол передачи файлов | Загрузка/скачивание файлов |

Эти протоколы образуют фундамент интернета. Без них вы не могли бы просматривать веб-страницы, отправлять почту, смотреть видео.

### 0.3 Ценность протоколов

Ключевая ценность протоколов — это **стандартизация** и **совместимость (интероперабельность)**:

- **Стандартизация**: все действуют по одним правилам, что снижает издержки на согласование
- **Совместимость**: системы разных производителей и на разных технологических стеках могут бесшовно стыковаться

Например, протокол HTTP позволяет браузеру Chrome обращаться к серверу Nginx, а Python-краулеру — собирать данные с Java-сайта. Chrome и Nginx не обязаны «знать» друг друга — достаточно, чтобы оба соблюдали протокол HTTP.

### 0.4 AI Agent тоже нужны протоколы

Чтобы AI Agent действительно «работал», ему нужно:
- вызывать внешние инструменты (узнавать погоду, отправлять почту, работать с базой данных)
- взаимодействовать с другими Agent (совместно выполнять сложные задачи)

Для этого нужны стандартизированные протоколы, задающие «как AI вызывает инструменты» и «как Agent общаются между собой». Так появились **MCP** и **A2A**.

## 1. Уровни протоколов Agent

Прежде чем углубляться в конкретные протоколы, давайте посмотрим на уровни связи в экосистеме Agent:

| Уровень | Протокол | Решаемая проблема | Аналогия |
|------|------|-----------|------|
| **1** | Function Call | Как AI вызывает локальные функции | Мозг отдаёт команды |
| **2** | **MCP** | Как AI подключается к внешним инструментам и источникам данных | Разъём USB-C |
| **3** | **A2A** | Как Agent взаимодействуют между собой | Корпоративный мессенджер |

::: tip Разбор этой таблицы построчно
**Уровень 1 (Function Call)**: это самая базовая способность больших моделей — запускать выполнение функций через вывод структурированных данных (JSON). Это основа «протоколов», но сам по себе это скорее способность, чем стандартный протокол.

**Уровень 2 (MCP)**: Model Context Protocol, выпущен Anthropic в ноябре 2024 года. Он стандартизировал способ подключения AI к внешним инструментам и источникам данных — так же, как USB-C унифицировал разъёмы зарядки для самых разных устройств.

**Уровень 3 (A2A)**: Agent-to-Agent Protocol, выпущен Google в апреле 2025 года. Он позволяет разным Agent находить друг друга, общаться и взаимодействовать — так же, как корпоративный мессенджер позволяет коллегам ставить задачи и переписываться.
:::

В этой главе мы сосредоточимся на двух формальных протоколах уровней 2 и 3: MCP и A2A.

## 2. MCP (Model Context Protocol)

### 2.1 Основная информация о протоколе

| Параметр | Содержание |
|------|------|
| **Полное название** | Model Context Protocol |
| **Инициатор** | Anthropic |
| **Дата выпуска** | 25 ноября 2024 года |
| **Официальная документация** | [modelcontextprotocol.io](https://modelcontextprotocol.io) |
| **Лицензия** | MIT License |
| **GitHub** | [github.com/modelcontextprotocol](https://github.com/modelcontextprotocol) |

::: tip Почему он называется «Context Protocol»?
**Context (контекст)** — это ключ к пониманию задачи большой моделью. Основная идея MCP в том, чтобы **позволить AI динамически получать нужную контекстную информацию**, а не запихивать всё в Prompt.

Например, когда AI нужно прочитать файл, вам не нужно копировать и вставлять содержимое файла — он напрямую обращается к файловой системе через MCP.
:::

### 2.2 Предыстория выпуска

В 2024 году с выпуском Claude 3.5 Sonnet в Anthropic обнаружили проблему: **каждый инструмент приходится интегрировать отдельно**.

Представьте:
- Вы хотите, чтобы AI читал репозиторий GitHub → нужно писать код интеграции с GitHub
- Вы хотите, чтобы AI запрашивал базу данных → нужно писать код интеграции с базой данных
- Вы хотите, чтобы AI работал с файловой системой → нужно писать код интеграции с файловой системой

Для каждой интеграции приходится повторно писать похожий код: аутентификацию, обработку ошибок, преобразование данных…

Anthropic написала в официальном блоге:
> "We're introducing the Model Context Protocol (MCP), an open protocol that standardizes how applications provide context to LLMs."

**Основная цель**: чтобы разработчики инструментов писали код один раз, а все поддерживающие MCP AI-приложения могли им пользоваться.

| Возможность | Английское название | Назначение | Пример |

| **Подсказки** | Prompts | Предопределённые шаблоны промптов | Шаблон ревью кода, шаблон письма |

### 2.5 Аналогия для понимания: разъём USB-C

MCP похож на **разъём USB-C**:

- **Раньше**: у каждого устройства был свой разъём зарядки (круглый, плоский, магнитный…)
- **Сейчас**: USB-C унифицировал зарядку и передачу данных для всех устройств
- **MCP**: унифицировал способ подключения AI ко всем инструментам

Разработчику инструмента достаточно один раз реализовать MCP Server, и все поддерживающие MCP AI-приложения (Claude, Cursor, Windsurf и др.) смогут использовать его напрямую.

### 2.6 Типичные сценарии применения MCP

| Сценарий | Описание | Пример |
|------|------|------|
| **Работа с локальными файлами** | AI читает/изменяет локальные файлы | Чтение кодовой базы, анализ лог-файлов |
| **Запрос к базе данных** | AI напрямую запрашивает базу данных | SQL-запросы, анализ данных |
| **Вызов API** | AI вызывает сторонние сервисы | GitHub API, Slack, почта |
| **Интеграция инструментов разработки** | AI использует инструменты разработки | Операции Git, команды терминала |

**Реальные примеры**:
- **Cursor/Windsurf**: через MCP подключаются к файловой системе, Git, терминалу
- **Claude Desktop**: через MCP подключается к приложениям для заметок, почтовым клиентам
- **Скрипты автоматизации**: позволяют AI выполнять автоматизированные задачи (резервное копирование, развёртывание, синхронизация данных)

## 3. A2A (Agent-to-Agent Protocol)

### 3.1 Основная информация о протоколе

| Параметр | Содержание |
|------|------|
| **Полное название** | Agent-to-Agent Protocol |
| **Инициатор** | Google |
| **Дата выпуска** | 9 апреля 2025 года |
| **Официальная документация** | [google.github.io/A2A](https://google.github.io/A2A) |
| **Лицензия** | Apache 2.0 |
| **GitHub** | [github.com/google/A2A](https://github.com/google/A2A) |

::: tip Почему инициатором стала Google?
Google выпустила A2A на конференции Cloud Next 2025, и это тесно связано с её корпоративной AI-стратегией.

Google считает, что будущее корпоративного AI — это не один супер-Agent, а **совместная работа нескольких специализированных Agent**: один отвечает за анализ данных, другой за генерацию кода, третий за обработку документов.

Этим Agent нужен стандартизированный способ общения между собой — так и появился A2A.
:::

### 3.2 Предыстория выпуска

MCP решил проблему «как AI подключается к инструментам», но осталась ещё одна: **как несколько Agent взаимодействуют?**

Представьте ситуацию:
- Agent A — «эксперт по анализу требований»
- Agent B — «эксперт по генерации кода»
- Agent C — «эксперт по тестированию»

Пользователь говорит: «помоги мне разработать функцию входа в систему»

После анализа требований Agent A должен передать задачу Agent B; написав код, Agent B должен дать Agent C его протестировать. Как им общаться между собой?

Google написала в официальном блоге:
> "A2A is an open protocol that enables AI agents to communicate with each other, facilitating collaboration across different frameworks and vendors."

**Основная цель**: позволить Agent, разработанным разными производителями на разных фреймворках, бесшовно взаимодействовать.

### 3.3 Что такое A2A?

<A2AVisualDemo />

**Три основные концепции**:

| Концепция | Английское название | Назначение | Аналогия |
|------|------|------|------|
| **Agent Card** | Визитка Agent | Описывает возможности Agent | Бейдж сотрудника |
| **Task** | Задача | Единица работы для выполнения | Наряд-заказ |
| **Message** | Сообщение | Содержание общения между Agent | История переписки |

<A2ADetailedDemo />

### 3.5 Аналогия для понимания: корпоративный мессенджер

A2A похож на **корпоративный мессенджер**:

- **Agent Card**: визитка каждого, где указаны имя, отдел, обязанности
- **Постановка задачи**: упомянуть кого-то (@) и назначить ему задачу
- **Общение в чате**: в процессе выполнения задачи можно в любой момент общаться
- **Отслеживание задач**: можно видеть прогресс и статус задачи

Разные Agent — как разные коллеги, а A2A позволяет им совместно выполнять сложные проекты.

### 3.6 Типичные сценарии применения A2A

| Сценарий | Описание | Пример |
|------|------|------|
| **Разработка ПО** | Несколько Agent совместно выполняют задачи разработки | Анализ требований → код → тестирование → развёртывание |
| **Корпоративный рабочий процесс** | Agent разных отделов совместно обрабатывают бизнес-задачи | HR-Agent + финансовый Agent + юридический Agent |
| **Умная поддержка** | Несколько специализированных Agent распределяют работу | Приём → ответ → перенаправление → запись |
| **Анализ данных** | Несколько Agent совместно анализируют данные | Сбор → очистка → анализ → визуализация → отчёт |

**Реальные примеры**:
- **Google Agent Space**: внутри компании несколько Agent совместно обрабатывают документы, почту, расписание
- **Команда разработки ПО**: Agent требований → Agent кода → Agent тестирования → Agent развёртывания
- **Система умной поддержки**: Agent приёма → Agent профессиональных ответов → Agent перевода на оператора

## 4. MCP vs A2A: сравнение и взаимосвязь

### 4.1 Ключевые отличия

| Критерий | MCP | A2A |
|------|-----|-----|
| **Инициатор** | Anthropic (2024.11) | Google (2025.04) |
| **Назначение** | Подключение AI к инструментам | Взаимодействие Agent с Agent |
| **Область связи** | Client-Server | Peer-to-Peer |
| **Формат данных** | JSON-RPC 2.0 | HTTP + JSON |
| **Аналогия** | Разъём USB-C | Корпоративный мессенджер |

### 4.3 Как выбрать?

| Сценарий | Выбор |
|------|------|
| Дать AI вызывать локальные функции или инструменты | Function Call |
| Использование сторонних инструментов (база данных, API, файловая система) | MCP |
| Построение системы совместной работы нескольких Agent | A2A |
| Нужны одновременно интеграция инструментов и совместная работа нескольких Agent | MCP + A2A |

## 5. Будущие тенденции протоколов

### 5.1 Развитие экосистемы

**Экосистема MCP** (по состоянию на начало 2025 года):
- Официальные серверы: файловая система, SQLite, Git, PostgreSQL и др.
- Серверы от сообщества: Slack, Notion, Figma, Stripe и др.
- Приложения с поддержкой MCP: Claude Desktop, Cursor, Windsurf, Zed и др.

**Экосистема A2A** (только что выпущена):
- Первыми поддержку добавили собственные Agent-продукты Google
- Open-source сообщество разрабатывает SDK для разных языков
- Корпоративные приложения находятся в стадии исследования

### 5.2 Процесс стандартизации

Сейчас протоколы Agent всё ещё в «эпохе междоусобиц»:
- MCP и A2A — два самых популярных
- Есть и другие новые протоколы, такие как ANP, AGP и др.
- В будущем они могут слиться или объединиться

Аналогия с развитием интернета:
- Раньше: сосуществовало множество протоколов локальных сетей
- Затем: стандартом стал TCP/IP
- Сейчас: протоколы Agent тоже, возможно, придут к единому стандарту

::: tip Ключевые моменты
| Протокол | Понимание в одну фразу | Дата выпуска | Инициатор | Сценарии применения |
|------|-----------|---------|--------|---------|

| **A2A** | «Корпоративный мессенджер» для взаимодействия Agent | 2025.04 | Google | Совместная работа нескольких Agent, делегирование задач |

**Ключевые выводы**:
1. MCP решает проблему «как AI получает внешние возможности»
2. A2A решает проблему «как несколько AI взаимодействуют»
3. Они дополняют друг друга и в будущем могут использоваться вместе
4. Протокол выбирается под конкретный сценарий — серебряной пули нет
:::
