## 0. Общая картина: в чём суть поиска?

Суть поиска — это задача **информационного поиска (Information Retrieval)**: по заданному запросу найти из огромного множества документов наиболее релевантные результаты и вернуть их, отсортировав по релевантности.

Этот процесс делится на два этапа:

- **Этап индексирования (офлайн)**: заранее обработать все документы и построить эффективную структуру поиска
- **Этап запроса (онлайн)**: когда пользователь вводит ключевые слова, быстро найти подходящие документы и отсортировать их

::: tip Почему нельзя использовать запрос LIKE в базе данных?
`SELECT * FROM products WHERE name LIKE '%красное платье%'` вроде бы умеет искать, но требует **полного сканирования таблицы** — построчной проверки каждой записи. Когда объём данных достигает миллионов, такой запрос становится недопустимо медленным. Инвертированный индекс превращает эту операцию O(n) в поиск за O(1).
:::

## 1. Инвертированный индекс: «сердце» поисковой системы

Традиционные базы данных используют **прямой индекс**: от ID документа к содержимому документа. А поисковая система использует **инвертированный индекс**: от ключевого слова к списку документов, его содержащих.

<InvertedIndexDemo />

| Тип индекса | Направление | Способ поиска | Сценарий применения |
|---------|------|---------|---------|
| Прямой индекс | Документ → содержимое | Знаешь ID — ищешь содержимое | Запрос по первичному ключу базы данных |
| Инвертированный индекс | Ключевое слово → список документов | Знаешь ключевое слово — ищешь документы | Полнотекстовый поиск |

::: tip Процесс построения инвертированного индекса
1. **Сбор документов**: получить все документы, которые нужно сделать доступными для поиска
2. **Токенизация (Tokenization)**: разбить документ на отдельные слова
3. **Построение сопоставления**: записать, в каких документах встречается каждое слово (а также позицию, частоту и т. д.)
4. **Персистентное хранение**: записать индекс на диск для быстрого поиска
:::

## 2. Токенизация и анализ текста

Токенизация — это первый шаг поисковой системы и одновременно главная сложность поиска для языков без явных границ слов. Английский естественным образом разбивается по пробелам, но во многих восточноазиатских языках (например, китайском) разделителей нет — одну и ту же строку символов можно разбить несколькими способами, и каждый вариант даёт разный смысл. Поэтому токенизатор должен опираться на словарь или модель, чтобы выбрать наиболее вероятную разбивку.

| Способ токенизации | Пояснение | Пример |
|---------|------|------|
| Стандартная токенизация | Разбиение по пробелам и пунктуации (английский) | "hello world" → ["hello", "world"] |
| Токенизация без пробелов | Разбиение на основе словаря или модели | "searchengine" → ["search", "engine"] |
| N-gram | Разбиение скользящим окном фиксированной длины | "search" → ["sea", "ear", "arc", "rch"] |
| Пользовательский словарь | Добавление специфичных бизнес-терминов | "iPhone16ProMax" как одно слово |

::: tip Конвейер анализа текста
Токенизация — лишь один шаг анализа текста, полный конвейер включает:
1. **Фильтрация символов**: удаление HTML-тегов, специальных символов
2. **Токенизация**: разбиение текста на слова (Token)
3. **Фильтрация стоп-слов**: удаление высокочастотных бессмысленных слов вроде «и», «в», «это»
4. **Расширение синонимами**: расширение «телефон» до «телефон, смартфон, мобильный»
5. **Стемминг**: приведение "running" к "run" (английский)
:::

## 3. Ранжирование по релевантности: какой результат самый «релевантный»?

Найти подходящие документы — лишь первый шаг, важнее **ранжирование** — поставить самые релевантные результаты на первые места.

| Алгоритм | Принцип | Особенности |
|------|------|------|
| TF-IDF | Частота слова (TF) × обратная частота документа (IDF) | Классический алгоритм, прост и эффективен |
| BM25 | Улучшенная версия TF-IDF с нормализацией по длине документа | Алгоритм Elasticsearch по умолчанию |
| Векторный поиск | Преобразование документа и запроса в векторы, вычисление косинусного сходства | Поддержка семантического поиска |

::: tip Интуитивное понимание TF-IDF
- **TF (частота слова)**: чем чаще слово встречается в документе, тем вероятнее, что документ релевантен этому слову
- **IDF (обратная частота документа)**: чем в меньшем числе документов встречается слово, тем выше его различающая способность
- слово «и» встречается во всех документах (низкий IDF), поэтому поиск по «и» не имеет смысла
- «Elasticsearch» встречается лишь в немногих документах (высокий IDF), поиск по нему позволяет точно локализовать
:::

## 4. Elasticsearch: самая популярная поисковая система

Elasticsearch — самая популярная на сегодня поисковая система с открытым исходным кодом, построенная на основе Apache Lucene и предоставляющая распределённый полнотекстовый поиск с RESTful API.

| Понятие | Пояснение |
|------|------|
| Index | Аналог «таблицы» базы данных, хранит однотипные документы |
| Document | Одна запись в формате JSON |
| Shard | Шард, разбиение индекса на несколько узлов |
| Replica | Реплика, обеспечивает высокую доступность и масштабирование чтения |
| Mapping | Определение типов полей, аналог Schema базы данных |
| Analyzer | Анализатор текста, задаёт правила токенизации |

::: tip ES vs база данных
Elasticsearch не предназначен для замены базы данных, а используется как слой поиска вместе с ней. Типичная архитектура: запись данных в базу → синхронизация в ES → поисковые запросы идут в ES → запросы деталей идут в базу данных.
:::

## 5. Оптимизация поиска: сделать поиск «умнее»

| Способ оптимизации | Пояснение | Эффект |
|---------|------|------|
| Синонимы | По «телефон» также находится «смартфон» | Повышение полноты (recall) |
| Исправление опечаток | "iphoen" автоматически исправляется на "iphone" | Отказоустойчивость |
| Автодополнение | Ввод «теле» подсказывает «телефон Apple» | Улучшение опыта |
| Подсветка | Подсветка совпавших слов в результатах поиска красным | Наглядность |
| Настройка весов | Вес совпадения в заголовке > вес совпадения в содержимом | Повышение точности |
| Фильтрация и агрегация | Фильтр по диапазону цен, бренду | Сужение диапазона |

## Заключение

Поисковая система — ключевая инфраструктура интернет-приложений. Поняв три ключевых понятия — инвертированный индекс, токенизацию и ранжирование по релевантности — вы овладеете сутью поисковых систем.

Вспомним ключевые моменты этой главы:

1. **Инвертированный индекс**: обратное сопоставление от ключевого слова к документу, ключевая структура данных поисковой системы
2. **Токенизация — основа**: токенизация китайского — ключ к качеству поиска, нужно выбрать подходящий токенизатор
3. **Ранжирование BM25**: оценка релевантности на основе частоты слов и частоты документов, алгоритм ES по умолчанию
4. **Архитектура ES**: шарды + реплики обеспечивают распределённость и высокую доступность
5. **Оптимизация поиска**: синонимы, исправление опечаток, автодополнение делают поиск умнее
