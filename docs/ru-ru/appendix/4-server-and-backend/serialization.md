# Сериализация: «перевод» данных

::: tip 🎯 Ключевой вопрос
**Как данные передаются по сети?** Это всё равно что спросить: как сделать так, чтобы слова одного человека понял другой? Сериализация решает именно проблему «перевода данных» — переводит объекты из памяти в формат, пригодный для передачи.
:::

---

## Необходимость сериализации данных

В процессе взаимодействия фронтенда и бэкенда данные должны несколько раз «трансформироваться», чтобы попасть с сервера к клиенту.

**Сценарий первый: полученные фронтендом данные «изменились»**

```javascript
// Бэкенд отправляет
Date birth = new Date(1990, 5, 15)

// Фронтенд получает
{ "birth": "1990-06-15T00:00:00Z" }  // строка!
```

Фронтенд хочет использовать `.getFullYear()`, но получает ошибку — потому что это не объект Date, а строка.

**Сценарий второй: искажение кириллицы/иероглифов**

```json
// Ожидается
{ "name": "Иван" }

// Фактически получено
{ "name": "Ð˜Ð²Ð°Ð½" }
```

Проблема кодировки символов приводит к искажению текста.

**Сценарий третий: узкое место производительности**

```json
// Ответ, содержащий список из 10000 товаров
{
  "products": [
    { "id": 1, "name": "...", "description": "...", ... },
    // ... ещё 9999
  ]
}
// Размер: 5.2 МБ, время передачи: 3.5 секунды
```

Избыточность формата JSON приводит к слишком большому пакету данных, что серьёзно влияет на производительность.

---

**Сериализация — это как «перевод»**: переводит объект из памяти в формат, пригодный для передачи, а принимающая сторона «переводит» его обратно.

---

## 1. Что такое сериализация/десериализация?

**Сериализация** (Serialization) — это процесс преобразования объекта в формат, пригодный для передачи.

**Десериализация** (Deserialization) — это процесс восстановления объекта из формата передачи.

### 1.1 Аналогия с отправкой посылки

| Отправка посылки | Сериализация | Пояснение |
| :--- | :--- | :--- |
| Упаковка предметов | Сериализация | Уложить предметы в коробку, наклеить ярлык |
| Транспортировка | Сетевая передача | Курьерская машина везёт до пункта назначения |
| Распаковка и извлечение | Десериализация | Получатель открывает коробку и достаёт предметы |

### 1.2 Зачем нужна сериализация?

| Причина | Пояснение | Пример |
| :--- | :--- | :--- |
| **Сетевая передача** | Сеть может передавать только поток байтов | Вызов API, связь по RPC |
| **Персистентное хранение** | Диск может хранить только байты | Сохранение объекта в файл, базу данных |
| **Межъязыковость** | У разных языков разные структуры данных | Объект Java → словарь Python |
| **Распределённый кеш** | Redis/Memcached хранят байты | Кеширование информации о пользователе |

### 2.1 JSON: самый универсальный

**Преимущества**:
- Хорошая читаемость, удобно отлаживать
- Поддерживается всеми языками
- Нативная поддержка в браузере (`JSON.parse` / `JSON.stringify`)

**Недостатки**:
- Большой размер (множество меток `{}` `""`)
- Не поддерживает богатые типы данных (Date, Map, Set преобразуются в строки)

**Сценарии применения**:
- Публичные API
- Связь фронтенда и бэкенда
- Конфигурационные файлы

### 2.2 XML: бывший лидер

```xml
<?xml version="1.0" encoding="UTF-8"?>
<user>
  <id>123</id>
  <name>Иван</name>
  <email>zhangsan@example.com</email>
  <age>28</age>
</user>
```

**Преимущества**:
- Чёткая структура, поддержка комментариев
- Поддержка сложных вложенных структур
- Есть валидация по Schema (XSD)

**Недостатки**:
- Большой размер, медленный парсинг
- Избыточность тегов (`<open></close>`)

**Сценарии применения**:
- Конфигурационные файлы (Spring, MyBatis)
- Протокол SOAP
- Сложный обмен данными

### 2.3 Protobuf: самый эффективный

```protobuf
// user.proto
syntax = "proto3";
message User {
  int32 id = 1;
  string name = 2;
  string email = 3;
  int32 age = 4;
}
```

**Преимущества**:
- Малый размер (на 30–50% меньше JSON)
- Высокая скорость (парсинг быстрее в 5–10 раз)
- Обратная совместимость (добавление полей не влияет на старые версии)

**Недостатки**:
- Нечитаемый (бинарный формат)
- Требуется определение в файле .proto
- Не поддерживает динамические типы

**Сценарии применения**:
- Внутренняя связь микросервисов
- Высокопроизводительные сценарии (игры, связь реального времени)
- Мобильные приложения (экономия трафика)

### 2.4 MessagePack: баланс читаемости и производительности

```json
// MessagePack — это бинарная версия JSON
// При одинаковых данных MessagePack примерно на 30% меньше JSON
```

**Преимущества**:
- Меньше и быстрее JSON
- Сохраняет модель данных JSON
- Поддерживает все типы JSON

**Недостатки**:
- Нечитаемый
- Менее эффективен, чем Protobuf

**Сценарии применения**:
- Нужна производительность, но не хочется использовать Protobuf
- Кеш Redis
- Сообщения WebSocket

## 3. Сравнение способов сериализации в разных языках

| Язык | Библиотека JSON | Библиотека Protobuf | Библиотека XML |
| :--- | :--- | :--- | :--- |
| **JavaScript** | `JSON.stringify()` | `protobuf.js` | `fast-xml-parser` |
| **Python** | `json.dumps()` | `protobuf` | `xmltodict` |
| **Java** | `Jackson` / `Gson` | `protobuf-java` | `JAXB` |
| **Go** | `encoding/json` | `proto` | `encoding/xml` |
| **C++** | `nlohmann/json` | `protobuf` | `tinyxml2` |
| **C#** | `System.Text.Json` | `Google.Protobuf` | `System.Xml` |

::: tip 💡 Рекомендации по выбору
- **Связь фронтенда и бэкенда**: JSON (удобно отлаживать)
- **Внутри микросервисов**: Protobuf (оптимальная производительность)
- **Конфигурационные файлы**: JSON или YAML
- **Интеграция со старыми системами**: XML (возможно, безальтернативно)
:::

## 5. Частые вопросы

### 5.1 Проблема сериализации дат

**Проблема**: объект Date после сериализации превращается в строку

```javascript
// До сериализации
const date = new Date('2024-01-01')

// После сериализации
JSON.stringify(date)  // "2024-01-01T00:00:00.000Z"
```

**Решения**:
```javascript
// Решение 1: преобразовать в временную метку
{ createdAt: date.getTime() }  // 1704067200000

// Решение 2: преобразовать в строку ISO
{ createdAt: date.toISOString() }  // "2024-01-01T00:00:00.000Z"

// Решение 3: пользовательская сериализация
JSON.stringify(obj, (key, value) => {
  if (value instanceof Date) {
    return { __type: 'Date', value: value.toISOString() }
  }
  return value
})
```

### 5.2 Проблема циклических ссылок

**Проблема**: циклические ссылки в объекте вызывают ошибку

```javascript
const obj = { name: 'test' }
obj.self = obj
JSON.stringify(obj)  // TypeError: Converting circular structure to JSON
```

**Решения**:
```javascript
// Решение 1: отфильтровать циклические ссылки
const seen = new WeakSet()
JSON.stringify(obj, (key, value) => {
  if (typeof value === 'object' && value !== null) {
    if (seen.has(value)) return
    seen.add(value)
  }
  return value
})

// Решение 2: использовать библиотеку flatted
import { parse, stringify } from 'flatted'
stringify(obj)  // автоматически обрабатывает циклические ссылки
```

### 5.3 Проблема искажения текста

**Проблема**: текст после сериализации искажается

**Причина**:
- Несоответствие кодировок символов (UTF-8 vs GBK)
- Метка BOM

**Решения**:
```python
# В Python убедитесь, что используется UTF-8
import json
json.dumps(data, ensure_ascii=False)  # не экранировать не-ASCII символы
```

```javascript
// В Node.js установите заголовок ответа
res.setHeader('Content-Type', 'application/json; charset=utf-8')
```

## 6. Практика: схема сериализации для e-commerce-системы

### 6.1 Анализ сценариев

| Сценарий | Выбор формата | Обоснование |
| :--- | :--- | :--- |
| **App → бэкенд-API** | JSON | Удобно отлаживать, единый для фронтенда и бэкенда |
| **Бэкенд → бэкенд RPC** | Protobuf | Оптимальная производительность, экономия трафика |
| **Кеш в Redis** | MessagePack | Меньше JSON, можно сериализовать сложные объекты |
| **Запись логов** | JSON | Удобно парсить инструментами анализа логов |

### 6.2 Пример кода

```javascript
// Ответ API (JSON)
app.get('/api/products/:id', async (req, res) => {
  const product = await db.getProduct(req.params.id)
  res.json({
    code: 0,
    data: product
  })
})

// Связь микросервисов (Protobuf)
// product.proto
syntax = "proto3";
message Product {
  int32 id = 1;
  string name = 2;
  int32 price = 3;
}

// Сервер
const proto = require('./product.proto')
const message = proto.Product.create(product)
const buffer = proto.Product.encode(message).finish()

// Клиент
const decoded = proto.Product.decode(buffer)

// Кеш Redis (MessagePack)
const msgpack = require('msgpack-lite')
await redis.set(
  `product:${id}`,
  msgpack.encode(product)
)
const cached = msgpack.decode(await redis.get(`product:${id}`))
```

## Краткий справочник терминов

| Термин | Английский | Объяснение |
| :--- | :--- | :--- |
| **Сериализация** | Serialization | Объект → поток байтов |
| **Десериализация** | Deserialization | Поток байтов → объект |
| **JSON** | JavaScript Object Notation | Самый распространённый текстовый формат |
| **XML** | Extensible Markup Language | Язык разметки, когда-то основной |
| **Protobuf** | Protocol Buffers | Эффективный формат с открытым исходным кодом от Google |
| **MessagePack** | - | Бинарная версия JSON |
| **Кодирование** | Encoding | Символ → байт |
| **Декодирование** | Decoding | Байт → символ |
