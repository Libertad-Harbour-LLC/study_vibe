# Протокол HTTP: «язык общения» фронтенда и бэкенда

::: tip 🎯 Ключевой вопрос
**Как работает HTTP?** Это всё равно что спросить: как разговаривают два человека? Нужно договориться о языке, грамматике, правилах диалога. HTTP — это и есть «протокол диалога» между фронтендом и бэкендом.
:::

---

## 0. Сущность HTTP

**HTTP** (HyperText Transfer Protocol, протокол передачи гипертекста) — это базовый протокол связи между фронтендом и бэкендом.

### 0.1 Аналогия с диалогом

| Элемент диалога | Соответствие в HTTP | Пояснение |
| :--- | :--- | :--- |
| Язык | Протокол HTTP | Язык, понятный обеим сторонам |
| Грамматика | Формат запроса/ответа | Как «говорить» |
| Процесс | Модель «запрос-ответ» | Вопрос-ответ |
| Завершение | Положить трубку | Закрытие TCP-соединения |

## 1. История развития HTTP

С момента появления в 1991 году HTTP прошёл через множество крупных обновлений.

<HttpProtocolDemo />

### 1.1 Сравнение версий

| Версия | Год | Ключевые улучшения | Типичные особенности |
| :--- | :--- | :--- | :--- |
| **HTTP/0.9** | 1991 | Поддержка только GET | Чистый текст, только запрос, без заголовков ответа |
| **HTTP/1.0** | 1996 | Добавлены POST/HEAD | Одно TCP-соединение на каждый запрос |
| **HTTP/1.1** | 1997 | Постоянные соединения | Keep-Alive, несколько запросов на одно соединение |
| **HTTP/2** | 2015 | Мультиплексирование | Бинарные фреймы, сжатие заголовков |
| **HTTP/3** | 2022 | На основе QUIC | Передача по UDP, решение блокировки начала очереди |

::: tip 💡 Зачем нужен HTTP/2?
Хотя HTTP/1.1 поддерживает постоянные соединения, запросы должны отправляться последовательно (следующий запрос можно отправить только после возврата ответа на предыдущий). HTTP/2 решает эту проблему через мультиплексирование, позволяя отправлять несколько запросов одновременно.
:::

## 2. Структура HTTP-запроса

### 2.1 Строка запроса

```http
GET /api/users/123 HTTP/1.1
```

Включает три части:
- **Метод**: GET, POST, PUT, DELETE и т. д.
- **URL**: путь к запрашиваемому ресурсу
- **Версия**: HTTP/1.1 или HTTP/2

### 2.2 Заголовки запроса

```http
Host: api.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer xxx
Content-Type: application/json
Content-Length: 45
```

Распространённые заголовки запроса:
| Заголовок | Пояснение | Пример |
| :--- | :--- | :--- |
| **Host** | Доменное имя сервера | `api.example.com` |
| **User-Agent** | Информация о клиенте | `Mozilla/5.0` |
| **Accept** | Принимаемый тип ответа | `application/json` |
| **Authorization** | Информация аутентификации | `Bearer token` |
| **Content-Type** | Тип тела запроса | `application/json` |

### 2.3 Тело запроса

```json
{
  "name": "Иван",
  "email": "zhangsan@example.com"
}
```

Тело запроса есть только у методов POST, PUT, PATCH и т. п.

## 3. Структура HTTP-ответа

### 3.1 Строка статуса

```http
HTTP/1.1 200 OK
```

Включает три части:
- **Версия**: HTTP/1.1
- **Код статуса**: 200, 404, 500 и т. д.
- **Текст статуса**: OK, Not Found и т. д.

### 3.2 Заголовки ответа

```http
Content-Type: application/json
Content-Length: 156
Cache-Control: max-age=3600
Set-Cookie: session=xxx; HttpOnly
```

Распространённые заголовки ответа:
| Заголовок | Пояснение | Пример |
| :--- | :--- | :--- |
| **Content-Type** | Тип тела ответа | `application/json` |
| **Content-Length** | Размер тела ответа | `156` |
| **Cache-Control** | Стратегия кеширования | `max-age=3600` |
| **Set-Cookie** | Установка Cookie | `session=xxx` |

### 3.3 Тело ответа

```json
{
  "code": 0,
  "data": {
    "id": 123,
    "name": "Иван"
  }
}
```

## 4. Подробно о методах HTTP

| Метод | Назначение | Тело запроса | Идемпотентность | Безопасность |
| :--- | :--- | :--- | :--- | :--- |
| **GET** | Получение ресурса | Нет | Да | Да |
| **POST** | Создание ресурса | Да | Нет | Нет |
| **PUT** | Полное обновление | Да | Да | Нет |
| **PATCH** | Частичное обновление | Да | Нет | Нет |
| **DELETE** | Удаление ресурса | Нет | Да | Нет |
| **HEAD** | Получение заголовков | Нет | Да | Да |
| **OPTIONS** | Запрос поддерживаемых методов | Нет | Да | Да |

### 4.1 GET vs POST

| Характеристика | GET | POST |
| :--- | :--- | :--- |
| **Расположение параметров** | Параметры запроса в URL | Тело запроса |
| **Кеширование** | Можно кешировать | По умолчанию не кешируется |
| **Закладки** | Можно добавить в закладки | Нельзя |
| **История** | Сохраняется в истории браузера | Не сохраняется |
| **Длина данных** | Ограничена (длиной URL) | Без ограничений |
| **Безопасность** | Параметры видны в URL | Параметры в теле запроса |

::: tip 💡 Когда использовать GET/POST?
- **GET**: запрос, получение данных
- **POST**: создание, отправка данных
- **PUT**: полное обновление (замена всего ресурса)
- **PATCH**: частичное обновление (изменение только указанных полей)
- **DELETE**: удаление ресурса
:::

## 5. Коды статуса HTTP

### 5.1 Классификация кодов статуса

| Категория | Пояснение | Типичные коды статуса |
| :--- | :--- | :--- |
| **2xx** | Успех | 200 OK, 201 Created, 204 No Content |
| **3xx** | Перенаправление | 301 постоянное, 302 временное, 304 не изменено |
| **4xx** | Ошибка клиента | 400 ошибка параметров, 401 не аутентифицирован, 404 не существует |
| **5xx** | Ошибка сервера | 500 внутренняя ошибка, 503 недоступен |

### 5.2 Часто используемые коды статуса

| Код статуса | Пояснение | Сценарий использования |
| :--- | :--- | :--- |
| **200 OK** | Запрос успешен | Успешный запрос GET, PUT |
| **201 Created** | Создание успешно | Успешное создание ресурса через POST |
| **204 No Content** | Нет содержимого | Успешное удаление через DELETE |
| **301 Moved Permanently** | Постоянное перенаправление | URL изменён навсегда |
| **302 Found** | Временное перенаправление | URL изменён временно |
| **304 Not Modified** | Не изменено | Кеш действителен |
| **400 Bad Request** | Ошибка параметров | Неверный формат параметров запроса |
| **401 Unauthorized** | Не аутентифицирован | Требуется вход |
| **403 Forbidden** | Нет прав | Вход выполнен, но недостаточно прав |
| **404 Not Found** | Не существует | Ресурс не существует |
| **500 Internal Server Error** | Внутренняя ошибка | Сбой сервера |
| **503 Service Unavailable** | Недоступен | Сервер на обслуживании или перегружен |

## 6. HTTPS: безопасный HTTP

### 6.1 HTTP vs HTTPS

| Характеристика | HTTP | HTTPS |
| :--- | :--- | :--- |
| **Протокол** | TCP | TCP + SSL/TLS |
| **Порт** | 80 | 443 |
| **Данные** | Передаются открытым текстом | Передаются зашифрованно |
| **Сертификат** | Не нужен | Требуется SSL-сертификат |
| **Производительность** | Чуть быстрее | Чуть медленнее (накладные расходы на рукопожатие) |
| **SEO** | Не влияет | Поисковые системы индексируют в приоритете |

### 6.2 Процесс работы HTTPS

1. **Client Hello**: клиент отправляет поддерживаемые наборы шифров
2. **Server Hello**: сервер возвращает сертификат и выбранный набор шифров
3. **Проверка сертификата**: клиент проверяет действительность сертификата сервера
4. **Обмен ключами**: с помощью асимметричного шифрования обмениваются сеансовым ключом
5. **Зашифрованная связь**: используется сеансовый ключ для симметрично зашифрованной связи

::: tip 💡 Преимущества HTTPS
- **Защита от прослушивания**: данные зашифрованы, третья сторона не может их прочитать
- **Защита от подмены**: проверка целостности данных
- **Защита от подделки**: SSL-сертификат подтверждает подлинность сервера
:::

## 7. Механизм кеширования HTTP

### 7.1 Заголовки кеширования

| Заголовок | Пояснение | Пример |
| :--- | :--- | :--- |
| **Cache-Control** | Стратегия кеширования | `max-age=3600` |
| **ETag** | Номер версии ресурса | `"33a64df551425fcc"` |
| **Last-Modified** | Время последнего изменения | `Wed, 21 Oct 2015 07:28:00 GMT` |

### 7.2 Стратегии кеширования

**Сильное кеширование**:
```http
Cache-Control: max-age=3600
```
В течение 3600 секунд браузер напрямую использует кеш и не отправляет запрос.

**Согласовательное кеширование**:
```http
ETag: "33a64df551425fcc"
```
Браузер отправляет `If-None-Match`, а сервер возвращает 304 (не изменено) или 200 (изменено).

## 8. Частые вопросы

### 8.1 Сущностное различие GET и POST

**Заблуждение**: различие GET и POST лишь в расположении параметров.

**Правда**:
- GET идемпотентен, многократные запросы дают одинаковый результат
- POST неидемпотентен, многократные запросы могут создать несколько ресурсов
- GET можно кешировать, POST по умолчанию не кешируется
- GET можно сохранить в закладки, POST нельзя

### 8.2 Блокировка начала очереди в HTTP/1.1

**Проблема**: хотя HTTP/1.1 поддерживает постоянные соединения, запросы должны отправляться последовательно. Если ответ на предыдущий запрос приходит медленно, последующие запросы вынуждены ждать.

**Решения**:
- Мультиплексирование HTTP/2
- Шардинг доменов (несколько доменов устанавливают несколько соединений)
- Пул соединений (ограничение числа параллельных соединений)

### 8.3 Преимущества HTTP/2

| Характеристика | HTTP/1.1 | HTTP/2 |
| :--- | :--- | :--- |
| **Формат передачи** | Текст | Бинарные фреймы |
| **Мультиплексирование** | Не поддерживается | Поддерживается |
| **Сжатие заголовков** | Нет | Алгоритм HPACK |
| **Server Push** | Не поддерживается | Поддерживается |

## Краткий справочник терминов

| Термин | Английский | Объяснение |
| :--- | :--- | :--- |
| **HTTP** | HyperText Transfer Protocol | Протокол передачи гипертекста |
| **HTTPS** | HTTP Secure | HTTP + SSL/TLS |
| **TCP** | Transmission Control Protocol | Протокол управления передачей |
| **SSL/TLS** | Secure Sockets Layer | Уровень защищённых сокетов |
| **Идемпотентность** | Idempotent | Многократные запросы дают одинаковый результат |
| **Постоянное соединение** | Keep-Alive | Несколько запросов через одно TCP-соединение |
| **Мультиплексирование** | Multiplexing | Одновременная отправка нескольких запросов |
| **Блокировка начала очереди** | Head-of-Line Blocking | Передние запросы блокируют задние |
